## 주문서 진입 전 재고 부족 422 — 장바구니로 돌아가 상품마다 표시
- 요청: 사용자 "재고 없는 것도 주문서에 추가되던데 백엔드에 말해놨어"(11-16) → 백엔드 요청 `customer-app/2026-11-16-request-draft-insufficient-stock.md`(order 0.8.0, LAN 배포됨) → 사용자 "응"(제안 순서 1번).
- 계약: cart·order·payment Dart 클라이언트를 백엔드 `4d99b94b` 로 다시 생성, `contracts.lock`(dart) 갱신. diff 영향 — 이 작업에 쓴 것은 order `POST /order-drafts` 422 `INSUFFICIENT_STOCK`(details[] field = sku, reason = `requestedQty=<q>;availableQty=<a>` 또는 `NOT_HANDLED`). 생성 타입이 바뀌어도 기존 시험 376개 모두 통과. order-orchestration(다시 배송 결제)은 아직 앱 의존성에 없어 생성하지 않음 — 다음 작업.
- 원인: 초안은 배송 선택 "다음"에서 만든다. `INSUFFICIENT_STOCK` 이 초안 거절 목록(`draftRejections`)에 없어 주문서로 넘어가 오류가 났다. 재고 0 이어도 장바구니가 품절(SOLD_OUT)을 주지 않은 줄은 선택된 채 초안으로 갔다.
- 한 일
  - `checkout.dart`: `draftRejections` 에 `INSUFFICIENT_STOCK`, `StockShortage`·`stockShortagesOf`(모르는 reason 은 수량 없이 — 지어내지 않음).
  - `checkout_controller.dart`: `stockShortageProvider` — 422 의 details 를 SKU 별로 담고, 다음 초안이 만들어지면 지움.
  - 배송 선택: 재고 부족이면 장바구니로 돌아가 "재고가 부족한 상품이 있어요. 장바구니에서 수량을 줄이거나 빼 주세요". 주문서로 바로 들어온 경우(`draftRejection`)도 같은 문구 + 장바구니 보기.
  - 장바구니 줄: 가용 a>0 "지금 a개까지 있어요", a=0 "품절이라 지금 살 수 없어요"(기존 문구 재사용). 수량을 a 이하로 줄이면 그 줄 안내는 사라진다.
  - **지금 주소로 배달하지 않는 상품은 장바구니에서 숨김**(사용자 2026-11-17 "그냥 안 보이게, 다시 그 주소로 돌아오면 보이게"): 근거는 서버 값만 — 장바구니 가용 `NOT_CARRIED` 또는 초안 422 의 `NOT_HANDLED`(`hiddenAtCurrentAddress`). 서버 장바구니에서 지우지 않고 선택만 서버로 뺀다(합계·주문에서 빠짐). 숨긴 품목은 "선택에서 뺐어요" 안내에 세지 않고, 선택 삭제·주문 초안에도 넣지 않는다. 담당 센터가 바뀌면 장바구니를 다시 열고 422 표시도 지워, 취급하는 주소로 돌아오면 다시 보인다(선택은 꺼진 채 — 고객이 다시 고름).
  - 다시 주문하기는 새 초안 생성 = 새 `Idempotency-Key`(기존대로 진입마다 새 키).
  - 목: 주문 `rejectNextDraftDetails`, 장바구니 `notCarriedAt`(센터별 취급 안 함). 캡처 도구에 `cart-stock-shortage`.

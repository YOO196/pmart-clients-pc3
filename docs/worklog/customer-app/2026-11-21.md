- 백엔드 확인 뒤 반영(사용자 "응"):
  - ① AI 상담 상품 답(백엔드 알림 `all/2026-11-20-notice-rag-product-info`, customer-assistant 0.3.0): `--only=customer-assistant` 다시 생성. `ChatAnswerState.productInfo`(`PRODUCT_INFO`) 추가 — 전에는 모르는 state 를 계약 위반으로 막아 서버 설정이 켜지면 상품 질문이 실패로 보였을 것. 답은 ANSWERED 처럼 문장 그대로(줄바꿈 그대로), 근거는 원래 숨김. 목 꼬리표 `#상품`. 시험 2개(계약 변환·화면).
  - ② 쿠폰·기간 할인(백엔드 요청 `customer-app/2026-11-21-request-coupons-discounts`, ADR-0082 — 사용자가 1차 제외를 바꿈. CLAUDE.md·`docs/apps/customer-app.md` 범위 문구 고침):
    - 생성: `tools/gen_api.dart` 에 `promotion-service` 추가(고객 경로 3개만 — /internal 은 원래 걸러짐), order 0.18.0·claim 다시 생성(contracts.lock b7d7381f). 앱 의존성 `pmart_api_promotion`.
    - 새 기능 `features/coupons`: 쿠폰함 `/me/coupons`(마이 메뉴 "쿠폰함", 회원만) — 쿠폰 받기(`POST /coupon-campaigns/{id}/downloads`, Idempotency-Key, 결과 불명이면 같은 키로 한 번 더, 422 COUPON_LIMIT_REACHED·COUPON_SOLD_OUT·NOT_ACTIVE 는 코드로 안내, 받은 뒤 목록·쿠폰함 다시 읽음)·사용 가능(`status=AVAILABLE`)·지난 쿠폰(전부 받아 AVAILABLE 제외). 남은 수량 null 은 무제한(0 아님).
    - 주문서: 결제수단 아래 "할인쿠폰" — "N개 보유"(조회 실패면 비움), 상자에 서버 견적 `couponDiscount` "N원 할인 적용됨" / 쓸 수 없으면 `coupon.reason` 사유(빨강)+쿠폰 빼기 / "쿠폰 선택". 고르기 `/checkout/coupons`(레퍼런스 6-5 카드, 한 장만·다시 누르면 빼기). 고르거나 빼면 `CheckoutSetup.couponId` → 새 의도로 주문서를 그대로 둔 채 다시 만듦(`DraftController.changeCoupon`). 새 "주문하기"는 쿠폰을 비움.
    - 막는 사유 `COUPON_NOT_APPLICABLE`(배너+쿠폰 빼기, 결제 버튼 문구), 결제 진입 422 `COUPON_NOT_APPLICABLE` 도 안내+쿠폰 빼기. `RE_QUOTE_REQUIRED` 는 원래 처리.
    - 금액: 상품금액 = `baseItemAmount`(없으면 itemAmount), 상품할인 `promotionDiscount`·쿠폰(견적 쿠폰 이름, 없으면 "쿠폰 할인") `couponDiscount` 줄(0 이면 없음). 주문 상세도 같은 줄. 앱은 할인을 계산하지 않음(목 주문서만 서버 규칙을 흉내).
    - 시험 `coupons_test.dart` 14개. 전체 customer_app 666 통과(버튼 글꼴 수정 전), 수정 뒤 analyze No issues·coupons/chat 38 통과.
    - 레퍼런스 비교(캡처 `coupon-pick`·`order-sheet-coupon`·`coupon-box*`): 카드 크기·글자·체크는 레퍼런스와 거의 같음(체크 색은 연보라). 남은 차이 — 레퍼런스의 쿠폰 묶음 머리("첫주문쿠폰")·더하기 쿠폰·아래 "총 7,000원"(합계는 고를 때 알 수 없음 — 서버 견적 전)·제목 위 "최대 할인 적용중" 배지·"총 할인받은 금액" 합계 줄·"배달팁 0원! N원 할인" 띠는 넣지 않음(계약에 없음 또는 앱 계산). 캡처의 주문서는 상품액이 작아 쿠폰이 "최소 주문금액이 모자라" 상태로 찍힘(적용된 모습은 시험으로 확인).
    - 하지 않은 것: 카드·상세·장바구니 할인가(서버 4단계 대기), 환불 화면의 할인 표시(서버 값 그대로라 변경 없음), 실서버(LAN) 확인.
- 장바구니 고침(사용자 "장바구니에서 봉투값 나오게 … 이것부터 고쳐줘"):
  - 봉투값: 회원 "결제금액"의 봉투값 줄을 "주문서에서 확인" → **100원**(사용자 선택 "정책 고정값 100원 표시" — 장바구니 계약에 값이 없음, `cartBagFeePolicy`). 실제 청구액은 주문서 견적 `bagFee`. 결제예정금액은 그대로 "주문서에서 확인"(앱이 더하지 않음).
  - 아래 창의 "결제 금액은 주문서에서 확인해요"·"배달팁·봉투값 안내" 버튼 없앰(비회원). 안내 창은 회원 결제금액의 [자세히]로만.
  - 최소주문(사용자 선택 "레퍼런스처럼 버튼 막기"): 서버 부족액(`minOrderShortfall`)이 0 보다 크면 주문 버튼을 회색 "최소주문금액을 채워주세요"로 막음(개수·금액 없이 — 레퍼런스 5-1). 부족액을 모르면(null) 막지 않음. 목 장바구니는 7,940원으로 시작해 바로 보임.
  - 시험: 목 장바구니에 `minOrderAmount`(기본 15,000) — 주문 흐름을 보는 시험·캡처는 0 으로(주문서 초안 최소주문 판정은 그대로). cart_min_order_test 에 막힘·다시 열림, cart_screen_test 에 문구 없음·봉투값 100원. 전체 668 통과(버튼 개수·금액 숨김 전), 수정 뒤 analyze No issues·장바구니 시험 25 통과. 캡처 `cart-min-order`(c-guest·c-member-amounts) 레퍼런스 5-1 과 비교 — 레퍼런스의 "N원 더 담으면 배달팁 0원"·쿠폰 띠는 없음(계약 값 없음).

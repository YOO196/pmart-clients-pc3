## 09:20 백오피스 운영자 로그인 Keycloak 전환 1단계(설정·로그인·갱신·로그아웃)
- 요청: 백엔드 요청 `../pmart-backend/docs/handoff/clients/2026-11-11-clients-request-backoffice-keycloak-login.md`(ADR-0054 결정 D·L) 확인 → "일단 keycloak 설정부터".
- 한 일(`web/backoffice`):
  - `vite.config.ts`·`package.json`: 빌드 모드 `lan-keycloak`(= `lan` + 로그인 Keycloak), 스크립트 `dev:lan-keycloak`·`build:lan-keycloak`. 기존 `lan`·`mock`·`local` 은 auth-service 로그인 그대로(결정 D: 옮기는 동안 두 방식).   - `src/api/keycloak.ts`(새): .well-known 읽기(발급자 일치 확인), Authorization Code + PKCE S256(state·nonce·verifier 는 이 탭 sessionStorage, 한 번만 씀), 토큰 교환·갱신(form-urlencoded 단순 요청 — CORS 사전 요청 없음), 로그아웃(`end_session_endpoint` + `id_token_hint`·`post_logout_redirect_uri=/login`). 갱신 `400/401`(invalid_grant) → 세션 종료, 5xx·네트워크 → 던짐(종료로 단정 안 함).
  - `src/api/sha256.ts`(새): LAN 은 `http://` 라 `crypto.subtle` 이 없어 순수 JS SHA-256 을 둠(보안 컨텍스트면 subtle).
  - `session.ts`: `iss` 가 Keycloak 이면 운영자 — `pmart_operator_id`·`realm_access.roles`(기본 역할 `default-roles-*`·`offline_access`·`uma_authorization` 제외)·`centers`. `typ`("Bearer")는 쓰지 않음. ID 토큰 `name`(없으면 성·이름)·`auth_time`.
  - `tokens.ts`: ID 토큰(메모리만, 새로고침 뒤엔 갱신 응답으로 다시 받음). `client.ts`: 갱신 훅·새로고침 복원이 로그인 방식을 따름(`refreshTokens`).
  - 화면: `/login` 은 Keycloak 모드면 "Keycloak 으로 로그인" 버튼만(비밀번호 안 받음), `/login/callback`(redirect_uri) 새 화면 — 실패 사유별 안내 + 다시 로그인. `/session` 은 Keycloak 모드면 `/auth/sessions/current`(Keycloak 토큰에 401)를 부르지 않고 토큰 만료·로그인 시각만, 비밀번호 변경은 Keycloak 계정 화면 링크로.
- 결정: OIDC 라이브러리(`oidc-client-ts` 등)를 추가하지 않고 직접 구현 — 규칙(요청 없이 라이브러리 추가 금지)과, 보안 컨텍스트가 아닌 LAN 에서 `crypto.subtle` 을 쓰는 라이브러리는 PKCE 가 안 되는 문제. 표준 OIDC 만 씀.
- 검증: typecheck·lint 통과, vitest 20파일 136개 통과(새 21개: SHA-256 표준값·RFC 7636 예시, 인가 주소, 토큰 교환·StrictMode 중복 1회, state·nonce 불일치, 기록 없음, 오류 복귀, code 거절·5xx, 발급자 불일치, 갱신·회전 유지·invalid_grant·5xx, 로그아웃 주소, 클레임, 화면 3개). `build:lan`·`build:lan-keycloak` 성공(MSW 미포함), `build:lan-keycloak` 결과를 vite preview + 헤드리스 Chrome 으로 열어 `/login` 에 Keycloak 버튼만 그려지는 것 확인. **실제 Keycloak 로그인은 미확인**(클라이언트 시험 계정 없음).

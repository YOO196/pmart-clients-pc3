- C2: 취소된 주문 상세 처리 내역에서 가장 최근 취소 클레임 상세를 읽어 자동 취소면 안내 줄. 조회 실패·로딩이면 안내 없이 처리 내역 줄만(눌러서 볼 수 있음).

- C4: 취소 접수 422 `DUPLICATE_CLAIM` → 진행 중 취소 클레임을 찾아 스낵바 "이미 취소가 진행 중이에요" + 처리 내역으로 이동. 못 찾으면 취소 화면에 안내만. 문구 `cancelDuplicate` 를 "이미 진행 중인 요청이 있어요" → "이미 취소가 진행 중이에요".
- C5: 기존대로 확인 — 주문 목록·상세 provider 가 autoDispose 라 열 때마다 다시 읽는다.
- 목: 진행 중 취소가 있으면 `DUPLICATE_CLAIM`, `seedSystemCancel(orderId)`(STOP_PENDING 부터, 시험용).

- 점검(읽기 전용 하위 에이전트 5개, 주요 2건은 직접 재확인):
  - ① PG 결제수단 늦게 뜸: 초안 생성 → 주문서 진입 재조회 → 그제서야 결제창 설정 조회 → 웹뷰 생성이 차례로. 결제수단이 ListView 맨 아래라 스크롤이 닿아야 로딩 시작.
  - ② 최소주문 미달 뒤 채워도 안 넘어감: `begin()` 이 기존 `purchaseIntentId` 를 재사용 → 서버(`DraftService.create`)가 견적 만료 전 같은 의도의 예전 초안을 그대로 돌려줌. 배송 방식만 바꿔도 같은 문제.
  - ③ 로그인 뒤 장바구니 빔: 병합 API 를 부르는 코드 없음(`CART_MERGE_CONFIRM` 미사용).
  - ④ 전화번호 형식: 주소 연락처 칸에 형식 검사 없음. 계약에도 pattern 없음. → 사용자 결정 필요(010만? 하이픈?).
  - ⑤ 다른 망에서 로그인 풀림: 앱 시작 세션 확인(`currentAccountId`)이 연결 실패도 null → 비회원으로 시작(토큰은 남음), 재시도 없음.
- 수정 ②: `begin()` 은 누를 때마다 새 의도, `enter()` 가 조건·장바구니 변경으로 새 초안을 만들 때도 새 의도. 목이 서버처럼 같은 의도 유효 초안을 돌려주게 함 → 옛 코드에서 새 테스트 2개와 기존 "배송 방식을 바꾸면 새 초안" 테스트가 실패함을 확인.
- 수정 ⑤: `currentAccountId` 는 세션 없음(4xx·만료)만 null, 연결 실패·결과 불명·5xx 는 던짐. `restore()` 는 그때 토큰을 두고 `sessionUnverifiedProvider` = true + 스낵바 "서버에 연결할 수 없어 로그인 상태를 확인하지 못했어요 [다시 시도]"(처음 한 번). 마이페이지에 같은 줄 + 다시 시도. 앱 복귀(`AppLifecycleListener`) 때 자동 재확인. LAN 밖에서는 고쳐도 요청은 실패한다(기대 동작: 로그인 유지 + 연결 오류).
- 수정 ① 일부: 배송 선택 "다음"과 동시에 결제창 설정 미리 조회, 주문서를 `SingleChildScrollView`+`Column` 으로(결제수단 바로 생성), "다음" 직후 주문서 진입의 중복 초안 조회 생략, 토스 위젯 첫 그리기 중 "불러오는 중" 표시. SDK 예열은 측정 뒤 결정(웹뷰 1개 더 듦).
- ③: `docs/backend-requests.md` BR-50(병합 앞 확인 질문 4개). 구현은 회신 뒤.

## 피킹 끝 → 패킹이 "지금 할 수 없어요"로 나가지던 것
- 실서버(사용자 시험, 주문 ORD-b50b6b64-…-S1): 피킹 완료 01:07:06Z → capacity 가 같은 작업자에게 PACK 배정 01:07:15Z → 패킹 시작 요청이 fulfillment 에 오지 않음(로그 없음).
- 원인: PDA 실행 입구(`TaskRunScreen`)가 작업 상태 ASSIGNED 일 때만 시작을 보냈다. fulfillment 는 배정을 capacity 사건으로 받아(`TaskService.applyAssignment`) 그 전에는 READY — PDA 가 "이 작업은 지금 할 수 없어요(준비)"를 띄우고 시작을 보내지 않음. 서버 시작 판정(`TaskRules.startRejection`)은 READY·ASSIGNED 둘 다 받고 배정자는 capacity 에 바로 묻는다.
- 고침: READY 도 시작을 보낸다(내 배정이 아니면 서버가 NOT_ASSIGNEE). 목: 시작 판정 READY 허용(서버와 같게), `packReadyBeforeAssignmentEvent`, 다음 작업은 내게 배정된 같은 주문 패킹 먼저.
- 확인: 새 위젯 테스트(고치기 전 실패 → 고친 뒤 통과), analyze 문제 없음, test 194개 통과, LAN APK 빌드·폰(SM-S931N) 설치됨 — 실기기 확인은 사용자 시험 대기.

- 한 일: 담기 단계에 "봉투 n번째"·아직 밀봉 안 한 수량·이 봉투 수량, 남은 게 있으면 밀봉 버튼 "이 봉투만 밀봉하고 라벨 — 남은 건 새 봉투에", 밀봉 뒤 "봉투 n개 밀봉 — 남은 m개를 새 봉투에". 포장 목록 "나누기"(2개 이상) → 줄마다 옮길 수량(하나 이상 옮기고 하나 이상 남김) → repackings(CONTENT_CHANGE, 한 주문 줄이 LOT 여러 줄이면 앞 줄부터, LOT 그대로) → 새 라벨 2장. 결과 불명 = 같은 나눔 같은 키, 거절은 CONTENT_MISMATCH/그 외 구분.
- 정하지 않은 것(문서 미결 — 추측 안 함): 10kg 자동 분할(Q-10), 주문당 출고 여러 개(D6-2). 봉투 무게 입력(weightG)은 넣지 않음.

  - 분배(DAS, 새 화면): 피킹 끝난 TRF 를 Wave 로 묶어 고름 → 상품 스캔 → 칸(TRF·MFC)마다 넣을 수량(작업 줄 shares 로 집은 몫 − BOX 에 담은 것) → "n개 넣었어요" → 칸 BOX 닫기(LPN 스캔 → `POST /sorting-results`, 한 BOX = 한 TRF). 넣은 것은 화면에만 — 서버에는 닫은 BOX 만.
  - 패킹: 예전 "분배" 화면(BOX 스캔 → 상품 → 봉인 = sorting-results) 이름만.
  - 검품: 출고대기 자리(통로 91) 스캔 → BOX → 잰 온도(선택, temperatureC) → 합격/불합격(사유), 불합격이 있으면 "패킹에서 다시 담아 닫은 뒤 다시 검품" 안내.
  - 상차(다시 짬): 도크(통로 90) 스캔 → 그 도크의 운행(`GET /cdcs/{cdcId}/trips` CHECKED_IN·SCHEDULED 중 dockCode) → 차량 ID·번호판 확인 → 운행 TRF 들의 합격 BOX 스캔 → TRF 마다 `POST /loading-results`(tripId·vehicleId·dockCode·구획 = 운행 tempClass) → `POST /trips/{tripId}/loading-completions`(입차 CHECKED_IN 만 — 아니면 "입차 등록되면" 안내·운행 다시 읽기). 상차완료 ≠ 출발.
- MFC 하차: mfc-inbound 입고 예정의 `packages`(LPN)를 박스 목록으로, `tripId`·`mfcId` 를 받음. 박스 검수(받은 박스·파손 표시)를 끝내면 `GET /mfcs/{mfcId}/inbound-trips` 에서 그 TRF 정차를 찾아 `POST /trips/{tripId}/stops/{seq}/handovers`(receivedLpns·damagedLpns). 인계 결과(기록·도착 전·정차 없음·불명 → 같은 키로 다시)는 안내만, 수령은 그대로 이어 함(인수 확정은 MFC 수령).
- 위치 카드 R-22·R-25 글자로: A~F 상온(E·F 생활용품)·G 냉장·H 냉동, 층 도크(B1 없음), 통로 93 바닥 레인, 오토스토어(C-6·F-7 통로 61~62, 단 1~16 두 자리). 목업 위치 코드도 맞춤.
- 시험: flutter analyze 문제 없음, mfc_app 전체 265 통과(분배 DAS·검품 출고대기/온도·상차 도크→상차완료·피킹 방식/지역 카트·하차 인계 본문·도크로 운행 찾기 새로, 적치 시험은 기능과 함께 뺌).
- 아직: MFC 수령 확정 `MfcReceiptPosted`(IV-8)는 백엔드 PC3 몫이라 그 전엔 CDC Transit 이 줄지 않는 게 정상(C-01). 지게차 보충은 설비 몫이라 PDA 에 없음 — 요청한 쪽에 회신 필요.

## DC 피킹 완료 뒤 자동으로 다음 피킹 받지 않기 (브랜치 mfc-app/cdc-pick-manual-next)
- 사용자: "PDA앱 DC로 해봤는데 출고대기로 넘어간다고 떴었는데 피킹작업이 다시 시작돼."
- 원인: 피킹 완료 화면(TaskDoneView)이 MFC 규칙(2026-11-13 "10초 뒤 자동 다음 작업")대로 10초 뒤 다음 작업 받기를 불렀다. 목에는 피킹 작업이 셋이라 곧바로 다음 피킹이 시작돼 되풀이처럼 보였다.
- DC 피킹만 `autoNext: false` — "다음 작업"을 눌러야 받는다. MFC 업무는 그대로 10초.
- 시험: cdc_pick 7 통과(완료 화면에서 12초 지나도 그대로인지 더함). 갤럭시 S23(R3CW20NBFDF)에 목·실서버 다시 설치.

## (PC 3) 에뮬레이터로 피킹→패킹 직접 눌러 본 결과와 고친 것
- 상황: 사용자 "캡처하면서 이동할 때 화면이 이상하게 넘어가거나 뜨는 시간·버튼 이상한 거 없었어?" — 캡처 도구(테스트 러너 정지 화면)로는 전환이 안 보여, 에뮬레이터(pmart_pda, 720×1440 = 360dp)에 목 빌드를 깔고 누를 때마다 0.3초 간격으로 화면을 떠서 확인.
- 고친 것:
  1. **피킹: 칸 몫을 보낸 직후 방금 끝낸 칸이 1초 넘게 다시 보였다**(확정 0/5, 같은 칸·같은 상품) — 보내고 단계는 "칸"으로 돌렸는데 작업 상세는 다시 읽기 전 옛 값. `PickingState.sentStop`(줄·칸·수량) + `sync()` 가 새 상세를 다 읽은 뒤 끝냄 → 그 사이 "보냈어요 · 서버 확인 뒤 다음 칸이 나와요"(`pick-sent-wait`). 시험: 지연 300ms 목에서 100ms 마다 옛 칸이 안 보이는지(고치기 전 코드로 실패 확인).
  2. **패킹: "배차 요청" 뒤 단추가 잠깐 다시 눌리게 보였다** — 성공하자마자 busy 를 풀고 출고는 나중에 다시 읽음. 출고를 다 읽은 뒤 busy 해제(`_reloadShipment`). 시험: 요청 뒤 단추가 다시 켜지지 않고 요청 1번(고치기 전 코드로 실패 확인).
  3. **작업 시작 화면: "불러오는 중이에요" → 글자 없는 빙글이로 바뀌어 깜빡여 보였다** → 시작 판정 대기도 "작업을 시작하고 있어요".
  4. **단계 칸 "✓ 장바구니"가 "장바…"로 잘림**(패킹 다섯 칸, 360dp) → 자르지 않고 칸에 맞게 줄임(`StepHeader` FittedBox).
  5. **피킹·패킹에서 "장바구니"와 "카트"가 섞임** → 피킹·패킹은 사용자가 쓰는 "장바구니"로(재고 이동의 카트는 그대로).
  6. **포장 라벨에 인계 숫자 6자리가 없었다** — fulfillment 계약은 "포장 라벨에 찍힌 `handoverCode`(6자리)"를 라이더 앱이 QR 대신 넣는다고 하는데, 라벨·미리보기·포장 목록은 시스템 값(`pkg-1`, `PKG:pkg-1:1`)만 보였다. `PackageView.handoverCode`(계약 매핑) → 라벨 ZPL 맨 위 크게(70), 포장 ID·버전은 작게, 미리보기 크게, 패킹 화면 포장 줄도 6자리(ADR-0070, 없으면 "번호 없음"). 목은 순번으로 6자리. 시험: ZPL·미리보기 값.
- 남긴 것: 앱을 처음 켤 때 시스템 시작 화면(연보라) 3.5초 → 시작 그림 1초 미만 — 에뮬레이터 debug 빌드라 느림, 실폰(특히 release)에서 다시 잴 것. 로그인 파일의 안 쓰는 `StartingScreen` 은 PC 1 몫.
- 확인: analyze 문제 없음, test 226개 통과, 에뮬레이터에서 피킹 5줄 → 패킹(패킹대·장바구니·배차·봉투 3개·라벨·출하대기 랙) → 끝까지 다시 눌러 위 1~6 이 고쳐진 것을 화면으로 확인.

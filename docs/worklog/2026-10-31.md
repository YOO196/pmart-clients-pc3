- (2) 앱 반영:
  - **결제 버튼 조건**:
    - 백엔드 코드(`DraftsController`·`CheckoutService`)를 보면 결제 진입 전 초안은 `DRAFT`·`REVIEW` 다. 앱은 `PAY` 일 때만 결제 버튼을 열었다. 그래서 실서버에서는 결제 버튼이 열리지 않았을 것이다.
    - 이제 `OrderDraft.awaitingCheckout`(DRAFT·REVIEW)에서 결제 버튼을 연다. `PAY` 는 결제 진입 뒤 결제창 정보가 있을 때만 쓴다.
    - 목도 같은 흐름으로 바꿨다: 초안은 REVIEW → 결제 진입 → PAYMENT_PENDING·PAY + payment.
  - **결제창 정보**:
    - 초안 `payment`(pgOrderId·amount·orderName·clientKey·expiresAt)를 `PaymentEntry` 로 옮긴다.
    - 결제 화면은 1초 간격, 최대 30초 동안 초안을 조회한다. 재고 확인 중(WAIT)이면 기다리고, PAY 면 결제창을 연다.
    - `expiresAt` 이 지났으면 결제창을 열지 않는다.
  - **확보 실패**: `checkoutFailure.code`(INSUFFICIENT_STOCK·SKU_NOT_HANDLED·CAPACITY_EXCEEDED·SLOT_NOT_SELECTABLE·CONFIG_REQUIRED·RESOURCE_EXPIRED)를 사유 문구로 보인다. 결제 화면과 주문서 배너 모두 해당한다.
  - **다시 결제**:
    - 실패하면 이번 결제 시도는 끝난다(서버가 자원을 푼다). 그래서 "주문서에서 다시 결제하기"로 주문서로 돌아가 새 Idempotency-Key 로 결제 진입한다.
    - 같은 결제창 정보를 다시 열던 예전 `retry()` 는 지웠다.
    - 주문서 refresh 는 초안이 REVIEW 로 돌아오면 "결제 진입함" 표시를 지운다.
  - **승인 요청**:
    - `POST /payment-confirmations` 로 orderId(=pgOrderId)·paymentKey·amount 만 보낸다.
    - 응답을 놓쳐도 다시 보내지 않고 초안 조회로 확인한다(결제 안내 §1⑤). 이전에는 같은 키로 3번까지 다시 보냈다.
    - stage 와 오류 코드는 accepted/rejected/unknown 으로만 나누고, 완료 여부는 초안 CONFIRMED 로만 판단한다.
  - **취소·실패 보고**: 결제창 취소(`PAY_PROCESS_CANCELED`)나 실패면 `POST /payment-authorization-failures` 로 알린다.
  - **422 CHECKOUT_BLOCKED**: 전용 문구를 보인다.
  - **결제창 SDK**: 토스 결제위젯 SDK 는 넣지 않았다(새 패키지라 결정이 필요하다). 실서버(PMART_ENV=local)에서는 `UnconnectedPgLauncher` 가 "결제창이 아직 연결되지 않았어요(개발 빌드)"로 끝내고, 서버에 실패를 알린다. 목은 그대로 `MockPgLauncher` 다.
  - **주문 조회**: `GET /orders`·`/orders/{id}` 는 이미 연결돼 있어서 바꾸지 않았다.

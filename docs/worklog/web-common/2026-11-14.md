- 결정:
  - silent 요청은 그동안 반영되지 않았다. 쿠키 요청이 "세션 끝남 → silent 로그인"을 전제로 해서 함께 넣었다.
  - silent 표시는 세션이 생기면(티켓 교환 성공) 지운다 — 한 탭에서 세션이 끝날 때마다 한 번씩 확인할 수 있고, `LOGIN_REQUIRED`·로그아웃 뒤에는 버튼만.
  - 쿠키 갱신의 결과 불명은 세션 끝으로 본다(다시 보내면 옛 쿠키 재사용). 서버가 사유를 알려 준 다른 거절(429 등)은 세션을 끊지 않는다 — 회신에 가정으로 적음.
  - 목 서버는 BODY 방식 그대로(서비스 워커는 HttpOnly 쿠키를 못 심는다). MSW 핸들러의 `request.credentials` 는 늘 `same-origin` 으로 보여서, credentials 시험은 `fetchImpl` 로 fetch 바로 앞의 Request 를 본다.

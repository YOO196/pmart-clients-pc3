- 사용자: "백오피스 콘텐츠 등록에 여전히 이미지 등록하는 부분이 없어. eum 프로젝트 참고해줄래?" — 기존에는 초안을 만든 뒤 초안 화면에서 파일 하나씩(역할·순서 직접 입력) 올리는 방식이라 등록 폼에는 이미지 영역이 없었다.
- Eum(`Eum-main/eum_backoffice` `ProductForm.jsx`) 방식: 폼 안에 상품 이미지·상세 이미지 영역, 고르는 즉시 미리보기, 대표 지정, 제거, 순서 번호. Eum 은 독립 업로드 API 가 있어 즉시 올리지만 PMart 계약은 이미지가 초안에 붙으므로(`POST /content-drafts/{draftId}/images`) 새 초안은 "초안 저장" 뒤 생긴 ID 로 차례로 올린다.
- 반영(`web/backoffice/src/features/contents/`):
  - `ImagePicker.tsx`: 역할별 3영역(대표 1장 — 다시 고르면 바꿈, 상세설명 여러 장 순서대로, 상세정보 표). 숨은 파일 입력 + "이미지 추가"/빈 영역 클릭, 미리보기(objectURL, 못 만들면 파일명), 순서 배지, ✕ 제거, 이미 올라간 이미지는 함께 표시(`AuthedImage`). 화면을 떠나면 미리보기 URL 해제.
  - `imageUpload.ts` `uploadPendingImages`: 한 장씩, 장마다 새 멱등 키, MAIN 은 sortOrder 0, 나머지는 기존 같은 역할 뒤에 이어 붙임. 한 장 실패해도 계속 올리고 실패 목록을 돌려준다(5xx 는 결과 불명).
  - 새 초안 화면: 폼 아래 이미지 영역. "초안 저장" → 초안 생성 → 진행 표시("이미지 n/m장 올리는 중") → 전부 성공이면 초안 화면으로, 일부 실패면 남아서 "n장 올렸고 m장 실패 + 초안 화면 열기" 링크, 실패한 장만 목록에 남는다.
  - 기존 초안 화면(DRAFT): 같은 영역에서 고르는 즉시 올리고 초안을 다시 읽는다. 이전의 파일·역할·순서 수동 입력 UI 삭제.
- 테스트: `imageUpload.test.ts` 2개(가짜 API 로 순서·키·실패 지속), `ImagePicker.test.tsx` 3개(고르기·제거·대표 교체·저장 뒤 전달 순서, 일부 실패 표시, 기존 초안 즉시 올림). **vitest 5 + jsdom 30 의 fetch 가 multipart 본문(jsdom Blob)을 못 보내** 화면 테스트는 올리기 함수를 `vi.mock` 으로 대체했다. 목 `images` 핸들러의 파일 검사는 `instanceof Blob` → 모양 검사로.
- 검증: `npm run typecheck`·`npm run lint`·`npm run test`(Vitest 61개) 통과. `npm run build:lan` 으로 dist 재생성.

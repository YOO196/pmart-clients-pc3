# 고객앱 레퍼런스 대비 차이 목록 (2026-11-04)

- 목적: 레퍼런스 캡처(`docs/customer-app-design/`, 제3자 앱, 로컬 전용)의 **구성**(화면마다 보이는 정보, 흐름과 단계)을 지금 고객앱과 비교한다. 화면 모양·브랜드·색·문구 톤은 가져오지 않는다(`customer-app-design-review.md` §5).
- 앞선 검토: `customer-app-design-review.md`(2026-10-24). 거기서 정한 "따라 하지 않음"(§1)과 결정(§2)은 다시 다루지 않고, 해당 항목은 "정책 결정 필요" 또는 "1차 제외"로만 표시한다.
- 기준
  - 현재 앱: `apps/customer_app/lib/` 의 화면(`features/*/presentation/*.dart`), 문구(`l10n/app_ko.arb`), 라우트(`router.dart`). 아래 표의 경로는 `features/` 아래 상대 경로다.
  - 서버 데이터: `../pmart-backend/contracts/openapi/*.yaml`(읽기만 함, 2026-11-04 작업 폴더 기준).
  - 캡처: 174장 중 대표 20장을 열어 확인했다. 나머지는 파일명과 앞선 검토를 근거로 했다. 캡처 파일 칸의 폴더명은 줄였다(예: `5. 장바구니` = `5. 장바구니 (비회원도 추가는 가능) @`).
- 분류
  - **클라이언트만으로 가능**: 계약에 이미 있는 데이터나 정적 안내로 앱만 고치면 된다.
  - **BR 필요**: 계약에 데이터나 경로가 없다. `backend-requests.md` 등록(기존 BR 번호 표기, 없으면 "신규")
  - **1차 제외**: `customer-app.md` 의 1차 제외 범위(쿠폰·프로모션·할인 배너·찜·재입고 알림·공유·AI 상담·포인트·1+1·증정 배지). 제안하지 않는다.
  - **정책 결정 필요**: 업무 문서에 규칙이 없거나 `[결정 필요]`·`[보류]` 인 항목이다. 사용자 결정 전에는 만들지 않는다.
  - **있음**: 이미 같은 구성이 있다(집계에서 뺌).
- 개인정보: 캡처에 보이는 이름·전화번호·주소·주문번호는 이 문서에 옮기지 않았다.
- `(미확인)` 표시는 코드나 캡처로 끝까지 확인하지 못한 항목이다.

## 19. 클라이언트만으로 바로 할 수 있는 것 (우선순위)

계약에 데이터가 이미 있고 업무 규칙과 충돌하지 않는 것부터 정했다. 표시 값은 모두 서버 값이고 앱 계산으로 확정하지 않는다.

1. **알림센터 + 알림 설정 + 알림 탭 이동**: `/me/notifications`, `/me/notification-settings`, `Destination`. 지금 화면이 아예 없다(§13). 푸시 수신은 BR-09 를 기다린다.
2. **리뷰 쓰기·내가 쓴 리뷰(사진 없이)**: `/me/review-eligibilities`, `POST /reviews`, `GET /reviews/{id}`(§12). 사진은 BR-07 뒤에 붙인다.
3. **배송현황 4단계 진행 표시 + 예약 시각·변경/취소 버튼 배치 + SSE 갱신**(§9): `OrderStatus`·`Shipment.state`·`stage`, `/deliveries/{id}/stream`.
4. **홈 배송 방식 요약 카드 + 심야 예약 안내**(§1): `/delivery-options` `eta`·`deliveryTip`·`NIGHT_TIME`·`earliestSlot`.
5. **홈 고정 탭(홈·랭킹·NEW) + 섹션 "전체보기" + kind별 배치**(§1): `HomeLayout.tabs`, `/storefront/tabs/{tabKey}`, `viewAllRef`.
6. **진행 중 주문 카드(홈)**: `GET /orders?status=` + `/deliveries/{id}/eta` 조합(§1). 조회 실패를 "주문 없음"으로 그리지 않는다.
7. **같은 상품 담기 / 품목별 장바구니 담기**(§10): `OrderLine.sku` → `POST /carts/{id}/items`. 담기 결과는 품목마다 서버 응답대로 안내한다.
8. **주문내역 상태 필터 + 목록 카드 버튼(취소·예약시간 변경·배달 현황)**, **주문 상세의 결제 방법·배달 정보(요청사항·품절 처리)·섹션 바로가기**(§10): `status` 파라미터, `GET /payments/{orderId}.method`, `deliveryNote`, `outOfStockPreference`.
9. **상품 상세 리뷰 목록 + 카드 `+` 바로 담기**(§4, §5): `/products/{id}/reviews`, `representativeSku`.
10. **장바구니 구성 보강**(§6): 수량 1의 휴지통, 선택 삭제(품목별 순차), "+ 상품 추가", CTA 안 담은 수·합계, 첫 구매 "적용 예상" 한 줄(`deliveryTip.reason`), 보관 기한(`expiresAt`), 배달팁·봉투값 안내 모달. 검색 화면의 하단 장바구니 요약 바(§3)도 같은 데이터로 만든다.

그다음 후보: 반품·교환 신청 화면 골격(품목·수량·사유 3그룹, §11. 자격 표시는 BR-15 회신 뒤), 주소 수정·삭제 화면(§14), 주문서 뒤로가기 확인·썸네일 줄(§7), 카테고리 상위 그룹 2열(§2), 온보딩(권한 안내·둘러보기 선택·마케팅 동의 결과 고지, §15), 홈 스켈레톤(§17).

## 1. 레퍼런스 홈 프로모션

### 공통 모양
- **위 탭:** 홈 · 할인 · 랭킹 · NEW · 기획전(5일장·가을 나들이 등)
- **섹션:** 제목, "전체 보기 >", 분류 칩(전체/과일·채소…), 가로 카드 또는 2줄 격자
- **카드:** 할인율·가격, 100g당 가격, 별점(리뷰 수), "N개 남음"
- **카드 배지:** 최저가 도전·신선보장·1+1·배민단독·5일장 특별가·19(주류)

### 우리 서버로 되는지 (storefront `Section.kind` = THEME, SEASON, WEEKLY_PICK, NEW, RANKING, HIGH_RATING)

| # | 섹션 | 모양 | 지금 우리 서버로 |
|---|---|---|---|
| 0 | 방금 본 상품과 비슷한 상품 | 가로 카드 | ❌ 추천 API 없음 |
| 1 | 일일특가(오늘 하루만) | 남은 시간 + 큰 카드, 1/6 넘기기 | ❌ 할인 — 1차 제외 |
| 2 | 시즌 기획(가을 나들이 총집합) | 칩 + 2줄 격자 | ✅ `SEASON` |
| 3 | 최저가 도전 | 칩 + 세로 목록 | ❌ 할인 배지 — 1차 제외 |
| 4 | 첫 주문 고객 TOP 30 | 순위 + 칩, 1/5 넘기기 | △ 순위(`RANKING`)는 되나 고객군 맞춤 진열 없음 |
| 5 | 오늘의 추천 행사(광고 카드 + 상품 3) | 행사 카드 가로 | ❌ 행사·광고 — 1차 제외 |
| 6 | 이번 주 꼭 사야 할 추천템 | 큰 사진 카드(레시피) | △ `WEEKLY_PICK` 있음, 레시피 콘텐츠 없음 |
| 7 | 엄선한 프리미엄 식품 | 칩 + 2줄 격자 | ✅ `THEME` |
| 8 | 간식 창고 | 칩(아이콘) + 격자 | ✅ `THEME` |
| 9 | 1+1 행사 | 1+1/2+1 칩 | ❌ 1+1·증정 노출 금지(Commerce L1164) |
| 10 | 꼼꼼히 고른 신상품(입점 2주) | 격자 | ✅ `NEW`·신상품 탭 |
| 11 | 마감세일 | 할인 전 가격에 줄 긋기 | ❌ 할인 — 1차 제외 |
| 12 | PB 상품 | 칩 + 큰 배너 + 목록 | △ `THEME` 로 가능, PB 배지 없음 |
| 13 | 주말 전통주 | 19 표시 카드 | △ `THEME` 로 가능. 주류는 PG 결제 인증 방식(앱 처리 미확인) |
| 14 | 이번 주 뷰티 특가 | 중복 쿠폰 문구 | ❌ 쿠폰·특가 |
| 15 | 리뷰 많고 평점 좋은 상품 | 격자 | ✅ `HIGH_RATING` + 정렬 '리뷰 많은 순'(search 0.3.0) |
| 16 | 지금 TOP 30 | 순위 + 칩 | ✅ `RANKING`·랭킹 탭 |
| 17 | 최근 찜 급상승 | 가로 카드 | ❌ 찜 없음 |
| 18 | 5천원 이하 식품 | 큰 카드 | ✅ `THEME`(서버가 담음) |
| 19 | 리빙템 | 칩 + 격자 | ✅ `THEME` |
| 20 | 평점 높은 냉장·냉동 | 가로 카드 | ✅ `HIGH_RATING`/`THEME` |
| 21·22 | 재구매율 높은 잎채소 · 잘 팔리는 구이용 소고기 | 품목이 돌아가며 바뀜 | △ `THEME` 로 담을 수는 있음. 재구매율 수치·자동 교체는 없음 |
| 23 | 카테고리별 무한 스크롤(총 N개) | 칩 + 2줄 격자 + 회사 소개 배너 | △ 검색 API(카테고리)로 만들 수 있음 |

**정리:**
- ✅ 되는 것: 시즌·테마·신상품·랭킹·평점 섹션, 칩, 전체 보기
- ❌ 막힌 것: 할인 관련, 찜, 추천, 재고 수("N개 남음")

## 2. 지금 구조에서 더할 수 있는 것

### A. 계약은 있고 앱만 하면 되는 것

| 항목 | 계약 | 상태 |
|---|---|---|
| 백엔드 회신 반영 BR-33·36·61·63 | claim 0.6.0 `GET /claims`, product-content 0.1.2/0.3.0, order 0.15.0, storefront 0.4.0 | **완료 2026-11-20**: 마이 "취소·반품 내역". 36·61·63 은 앱이 이미 맞아 표만 정리 |
| 최근 검색어 | search `GET/DELETE /me/recent-searches`, `DELETE …/{keyword}` | **완료 2026-11-20**. 인기 키워드(`suggestions.popular`)는 q 가 있어야 와서 빈 화면에 못 씀 |
| 회원 탈퇴·철회 | customer `POST /me/withdrawals`, `GET …/{id}`, `POST …/revocations` | **보류**: 아래 "탈퇴" 참고 |
| 주소 삭제 | customer `DELETE /me/addresses/{id}` | **완료 2026-11-20**: 주소 관리 "편집" → 주소 편집 |
| 문의 사진 첨부 | case `POST /inquiry-photos`, `POST /inquiries/{id}/photos`, `GET /inquiry-photos/{id}`, 작성 `photoIds` | **완료 2026-11-20**: 작성할 때 첨부·상세에서 보기. 남긴 문의에 보완(`…/photos`)은 남음 |
| 문의 만족도 | case `POST /inquiries/{id}/satisfaction`(답변 뒤 1~5점 + 한 줄, 한 번) | **완료 2026-11-20**(레퍼런스 고객센터 2-2-2 모양) |
| 문의 닫기 | case `POST /inquiries/{id}/closures`(닫을 때 만족도 선택) | **완료 2026-11-20**(확인 창, 다시 열기 없음) |
| 배달 완료 증빙 | execution `GET /deliveries/{id}/delivery-proof`, `…/evidence-photos/{photoRef}` | 남음 |
| 배너 | storefront `GET /storefront/banners`(HOME_MIDDLE·CATEGORY) — 홈 응답 안 배너는 이미 씀 | 남음 |
| 100g/100mL당 가격 | storefront `unitPrice`, product-content `netContent`·`unitPrice` | **결정 필요**: 백엔드 결정 문서 L-10 은 "표시 안 함" |
| 로그아웃 서버 알림 | auth `POST /auth/logouts` | 남음(지금은 기기 토큰만 지움) |
| 카테고리 전용 필터 | product `GET /categories/{id}/filters` | 남음(지금은 검색 필터) |

**탈퇴(보류 사유)** — 계약에 다음이 없어 짐작하지 않았다. 요청서로 확인할 것.
- 접수(202 `CommandResponse`) 응답에서 `withdrawalId` 를 어디서 받는지(`resultId` 인지)
- 앱을 다시 켰을 때 진행 중인 탈퇴를 찾는 길: `GET /me` 에 상태만 있고 ID 가 없다. 없으면 철회할 수 없다.
- 문서(`customer-app.md` 탈퇴)의 "재인증" 방식
- BR-64(탈퇴 번호 1달 재가입 금지)와의 연결

### B. 레퍼런스에 있고 앱·계약 모두 없는 것 (백엔드 작업 필요, 추정)
- **방금 본 상품과 비슷한 상품, 품절 상품 "비슷한 상품":** 추천·유사상품 API. 계산 방식 미정(Commerce L1052).
- **첫 주문 고객 TOP 30:** 고객군 맞춤 진열(storefront).
- **재입고 알림 받기/받지 않기:** 알림 신청 API(notification 등). 정책도 미승인.
- **"N개 남음"·센터별 품절 표시:** 목록 카드 재고 필드(storefront·search). todo #12·#15.
- **"마지막으로 둘러보기", 레시피형 추천 콘텐츠:** 진열 API(`customer-app.md` §5 결정 필요).
- **검색어 오타 교정("이것을 찾으셨나요"):** search 에 있는지 확인 필요.
- **현금영수증 · 교환 신청 화면 · 라이더 안심번호 · 실시간 상담원 · 매장 위치 지도:** 백엔드 `pending-user-decisions.md` L-8~L-13 "나중에/미정".

### C. 1차 제외로 정한 것 (하려면 정책 결정부터)
- **쿠폰·프로모션·할인:** 할인 탭·배너, 할인율·1+1·마감세일 배지. overview §4 L54, Commerce L52-54·L1164. promotion-service 는 "3단계 — 1차 비활성".
- **찜·재입고 알림·공유·추천:** "조건부, 승인 대상"(Commerce L94·L332·L1146).
- **선물함·상품권·포인트·멤버십:** 미도입(Commerce L1662·L1812).
- **주류:** 자체 성인인증 화면(레퍼런스 13 의 이름·주민번호·통신사)은 만들지 않는다. PG 결제 인증(payment `adultVerified`).

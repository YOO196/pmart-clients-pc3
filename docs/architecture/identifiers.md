# 클라이언트가 지킬 식별자 규칙

정본: `code-and-pick/baro-pick-docs` `09.채번 식별자 지침/바로픽_채번_식별자_통합지침.md`(2026-11-10 확정본 — 저장소 밖, API 로 읽기만). 아래는 앱·백오피스에 필요한 부분만 옮긴 요약이다. 충돌하면 정본을 따른다.
지침의 "확정"은 규칙의 확정이다 — 서버 반영은 지침 12장 이행 목록을 따라 차례로 된다(아래 "서버 반영" 칸).

## 1. 다루는 법
| 규칙 | 클라이언트에서 |
|---|---|
| 내부 ID(`ORD-…`, `PKG-…`, `LOT-…` 등)는 불투명 문자열 | **파싱하지 않는다.** 접두어로 종류를 판단하지 않는다. 서버가 준 값을 그대로 보낸다 |
| 내부 ID 를 사람에게 보이지 않는다 | 표시는 표시 번호(`orderNo`·`document_no`)가 생기면 그것으로. 그 전에는 지금처럼 보이되 바꿀 자리로 표시 |
| 코드·외부값은 문자열 | 앞자리 0 보존, 숫자로 바꾸지 않는다 |
| 객체는 정본 서비스만 발급 | 클라이언트는 ID 를 만들지 않는다(멱등 키·요청 ID 는 예외 — 객체 ID 가 아님) |
| 형식이 맞아도 존재·센터·권한·상태는 서버가 검사 | 형식 검사는 안내용(잘못 스캔했는지)일 뿐 |

## 2. 사람·스캐너가 읽는 코드(형식 검사 가능)
| 코드 | 형식 | 예 | 서버 반영 |
|---|---|---|---|
| SKU | `^[EB]-[0-9]{8}$` (E 낱개, B 제조사 밀봉 묶음) | `E-00000001` | 구현 |
| MFC 위치(선반·피킹) | `{온도 A/C/F}-{구역 영문1+숫자1}-{랙 2}-{단 1~9}-{칸 2}` | `C-S1-03-2-04` | 구현(ADR-0042) |
| MFC 위치(그 밖) | `{접두 3}-{온도}-{번호 2}` — `RCV` 수령, `PAK` 포장, `QRT` 격리, `DSP` 출고 대기, `RTN` 회수, `DSL` 폐기, `CRT` 카트 | `RCV-C-01` | 구현 |
| 센터 | `^(CDC[0-9]{2}|MFC-[A-Z]{2,4}-[0-9]{2})$`, 최대 32자 | `MFC-BSN-01` | 미반영(이행 1) |
| 라벨 스캔 값 | `{유형}:{id}:{버전}` — 기준은 포장 QR | `PKG:{packageId}:{packageVersion}` | 포장만 구현 |
| BOX·PLT | `^(BOX|PLT)-[0-9]{8}$` (번호 자체가 스캔값) | `BOX-50000001` | 미반영 |
| 토트·PDA | `TOTE-{6}`, `PDA-{6}` | `PDA-000028` | 미반영 |

## 3. 사람이 보는 번호
| 번호 | 형식 | 쓰는 곳 | 서버 반영 |
|---|---|---|---|
| 고객 주문번호 `orderNo` | `P{YYMMDD}-{Crockford Base32 6}` 예 `P261110-7K3M9Q`. 입력 정규화: 대문자, 공백 제거, `O→0`, `I·L→1` | 고객앱·백오피스 주문 표시·검색(지금은 `ORD-UUID` 를 보임 — 이행 5) | 미반영(이행 4) |
| 문서 번호 `document_no` | `{유형}-{YYYYMMDD}-{6}` 예 `TSK-20261110-000123` (유형 SHP·PKG·HOV·TSK·MOV·RCV·CNT·ADJ·DSP·EXC·TRF…) | PDA·백오피스 작업·입고·이동·실사 표시 | 미반영(이행 3) |
| LOT 현장 표시 | 제조사 LOT 원문 + 소비기한(내부 `LOT-UUID` 는 보이지 않음) | PDA 품질검사·피킹 | — |

## 4. 구현된 ID 모양(목 데이터를 맞출 때)
- 작업: `{shipmentId}-PICK`·`-PACK`·`-RETURN`, 작업 라인 `{taskId}:{orderLineId}`, 출하 `{orderId}-S1`, 주문 라인 `{orderId}-L{n}`.
- MFC: 포장 `PKG-`, 인계 `HOV-`, 입고 검수 작업 `TSK-INS-`, 적치 작업 `TSK-PUT-`, 회수 입고 `RRC-`, 이동 `MV-`, 실사 `CNT-`, 회수 검수 `RIN-`, 로트 `LOT-`, 회수 LOT 참조 `RET-{claimId}`.
- 작업자 ID = 운영자 ID(`OP-…`). 사번(`EMP-`)은 인사 정본이 생길 때만.

## 5. LOT (지침 G-06)
- LOT 번호(`LOT-UUID`)는 시스템이 발급한다. 작업자가 만들지 않는다.
- 동일 배치 판정: SKU + 제조사·공급사 + **제조사 LOT 원문** + 제조일자. 식품의 LOT 불명 수량은 판매 가능으로 바꾸지 않는다.
- PDA 품질검사: 포장의 LOT 표기를 **스캔**(카메라·스캐너)해 `sourceLotRef` 로 보낸다. 표기가 없으면 작업자가 "LOT 표기 없음"을 눌러 확인한다(사용자 결정 2026-11-10). 소비기한·제조일은 달력으로 고른다.

## 6. 멱등 키
- 앱이 만드는 키는 UUID(36자) — 서버 합성 키 길이 규칙(M-11)에 걸리지 않는다. 형식을 바꾸지 않는다.

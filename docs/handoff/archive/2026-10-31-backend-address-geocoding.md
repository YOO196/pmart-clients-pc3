# [pmart-clients → pmart-backend] 주소 → 좌표 변환 API 요청 (BR-30, BR-29 후속) (2026-10-31)

- 관련: `docs/backend-requests.md` BR-29(주소 좌표의 출처)·BR-30(이 요청), 백엔드 안내 `2026-10-30-clients-notice-customer-addresses.md`(배송 가능 판정은 좌표로만)
- 결정(사용자, 2026-10-31): 주소 좌표는 **카카오**로 얻는다. 키가 필요한 변환은 **서버**가 하고, 앱은 주소 검색과 지도 핀 조정만 한다.

## 1. 왜 필요한가
- `POST /me/addresses` 에 `geo` 가 없으면 `serviceability=UNKNOWN` 이다. 그러면 쇼핑 주소로 골라도 담당 MFC 가 정해지지 않고, 주문 초안도 만들 수 없다.
- 앱에서는 주소를 좌표로 바꿀 수 없다. 카카오 로컬 API 는 **REST API 키**가 필요한데, 이 키는 비밀값이라 앱에 넣지 않는다(저장소 규칙).
- 지금은 개발 빌드에만 "시험 좌표(서면역)" 버튼을 임시로 두고 있다. 정식 기능이 아니다.

## 2. 고객앱 화면 흐름(예정)
1. 고객이 **다음(카카오) 우편번호 검색**으로 도로명주소를 고른다. 키 없이 쓰는 무료 웹 화면이다.
2. 앱이 **이 요청의 API** 로 도로명주소를 좌표로 바꾼다.
3. 그 좌표에 **카카오 지도**(Android 지도 SDK, 네이티브 앱 키)를 띄우고, 고객이 핀을 끌어 위치를 맞춘다.
4. 최종 좌표를 지금 계약 그대로 `POST /me/addresses` 의 `geo{lat,lng}` 로 보낸다. 주소 계약은 바꾸지 않는다.

## 3. 요청 API (안 — 경로·이름은 백엔드가 정한다)

### 3.1 주소 → 좌표 (필수)
`GET /api/v1/address-geocodes?query=<도로명주소>`. customer-service 쪽이 자연스러워 보이지만 판단은 백엔드에 맡긴다.
- **권한:** 고객 토큰. 주소 등록이 회원 전용이므로 비회원 토큰까지 열 필요는 없다고 본다.
- **응답 예:**
  ```json
  {
    "results": [
      { "roadAddress": "부산 부산진구 …", "jibunAddress": "…", "zoneNo": "47285",
        "lat": 35.1578, "lng": 129.0597 }
    ]
  }
  ```
- **결과 0건:** 200 + 빈 `results` 를 준다. 앱은 "주소를 찾지 못했어요"를 보이고 다시 검색하게 한다.
- **조회 실패와 0건을 구분해 달라:**
  - 카카오 장애·타임아웃: 503 `LOOKUP_FAILED`, `retryable=true`
  - 무료 사용량 소진(카카오가 429 를 줌): 503 또는 429 `QUOTA_EXCEEDED`
  - 앱은 조회 실패를 "검색 결과 없음"으로 보이지 않는다(저장소 규칙).
- 카카오 원 API: `GET https://dapi.kakao.com/v2/local/search/address.json?query=…`, 헤더 `Authorization: KakaoAK {REST API 키}`.

### 3.2 좌표 → 주소 (선택)
`GET /api/v1/address-reverse-geocodes?lat=&lng=`
- 고객이 핀을 옮겼을 때 "이 위치: ○○로 12" 를 보여 주는 용도다. 없으면 앱은 처음 고른 도로명만 보인다.
- 카카오 원 API: `GET https://dapi.kakao.com/v2/local/geo/coord2address.json?x={lng}&y={lat}`.

## 4. 키·설정
- **REST API 키**는 사용자가 이미 `deploy/lan/.secrets/backend.env` 의 `KAKAO_REST_API_KEY` 에 넣어 두었다.
  - 카카오 콘솔의 "디폴트 REST API 키"다.
  - 클라이언트는 값을 보지 않았고, 이름과 위치만 확인했다.
  - 변수 이름과 파일은 백엔드 render 방식에 맞게 바꿔도 된다.
- 같은 파일에 `TOSS_SECRET_KEY` 도 있다. 백엔드는 이미 `PMART_TOSS_SECRET_KEY` 를 `.secrets` 에서 쓰고 있으니(payment-service), 어느 쪽을 정본으로 할지 정리해 달라.
- **호출 허용 IP**(권장): 카카오 콘솔 REST API 키 설정에 LAN 서버의 외부 IP 를 등록하면, 키가 새도 다른 곳에서는 쓰지 못한다. 외부 IP 는 백엔드가 확인해 사용자에게 알려 주면 된다.
- **무료 사용량**(카카오 문서 2026-10-31 확인):
  - 주소→좌표·좌표→주소는 각각 하루 100,000건이다.
  - 계정에서 카카오맵을 처음 켠 앱에만 무료 사용량이 있다.
  - 비즈월렛을 연결하지 않으면 사용량을 넘겨도 과금 없이 429 로 막힌다.
  - 같은 질의 결과를 짧게 캐시하면 사용량을 아낄 수 있다(선택).
- 로그: 주소 원문은 개인정보다. 요청 질의와 결과 주소를 로그에 남기지 않는다(마스킹).

## 5. 확인 부탁
1. 경로·서비스·권한(고객만 vs 비회원 포함)
2. 좌표 → 주소(3.2)도 이번에 할지
3. `POST /me/addresses` 에서 받은 `geo` 를 그대로 믿을지, 도로명과 너무 멀면 거절할지. 앱은 핀 조정 범위를 제한하지 않을 생각이다.
4. LAN 배포 시점과 안내 문서

## 6. 클라이언트 쪽 일정
- 이 API 가 계약에 들어오면 앱에 우편번호 검색 → 좌표 → 지도 핀 조정 화면을 붙인다.
- 지도는 `kakao_map_sdk` 패키지로 붙일 예정이다. 앱 키는 사용자가 클라이언트 저장소의 git 제외 파일에 넣어 두었다.
- 그때까지는 개발 빌드의 시험 좌표 버튼으로 시험한다.

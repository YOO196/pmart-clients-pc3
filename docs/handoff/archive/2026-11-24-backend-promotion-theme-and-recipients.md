# 행사 대상에 홈 편성 테마 추가 · 지정 발급 쿠폰은 만들 때 받을 고객 지정 요청

보낸 앱: backoffice (PC 2)
받는 백엔드 영역: platform (promotion-service 0.2.1 — ADR-0082 이어서, storefront 테마 참조)

## 1. 기간 할인 대상에 테마(THEME)
- 근거: 사용자 2026-11-24 — "홈 진열 편성에서 테마의 목적이 할인을 위한 목적이 아닌가?" → "행사 대상에 테마도 추가".
- **바뀌는 결정**: 업무 원문 Commerce §6.3·6.4 "일반 시즌/브랜드 테마는 할인 행사 없이 상품을 묶어 소개 … 할인·행사 권리를 생성하지 않는다"를 사용자가 바꿨다. 이제 테마를 기간 할인의 대상으로 고를 수 있어야 한다.
- 지금: `PromotionTarget.type` = `SKU`·`CATEGORY` 뿐. 테마 상품을 할인하려면 SKU 를 하나씩 넣어야 하고, 테마 상품이 바뀌어도 할인은 따라가지 않는다.
- 요청:
  - `PromotionTarget.type` 에 `THEME` — `id` = 편성 테마 `sectionId`(`T-…`). 대상 = **그때 게시된 진열 버전에서 그 테마에 든 상품들(의 SKU)**. 테마 상품이 바뀌면 할인 대상도 따라감(카테고리처럼 "그 아래 전부").
  - 테마가 게시본에 없으면(초안에만 있거나 빠짐) 제출 때 `problems`(예: THEME_NOT_PUBLISHED) — 승인 뒤 테마가 빠지면 할인도 멈추는지(권장) 회신에 적어 주세요.
  - `RANKING_AUTO`(자동 랭킹) 테마는 상품이 자동으로 바뀌므로 대상에서 막을지 정해 주세요(화면 제안: 막음 — 일반 테마만).
  - 행사 상세 `targets[]` 에 테마 이름(`title`)을 실어 주면 화면이 ID 대신 이름을 쓴다.
- 받은 뒤 화면: 행사 만들기의 대상 고르기에 "홈 테마" 탭(게시된 테마 목록에서 고르기), 편성 테마 카드에 "이 테마로 기간 할인 만들기" 바로가기.

## 2. 지정 발급(ADMIN) 쿠폰 — 만들 때 받을 고객을 지정
- 근거: 사용자 2026-11-24 — "직원 지정 발급을 눌러도 고객 id 를 넣는다던가 찾는 칸 자체가 없는데". 지금 계약은 발급을 **승인되고 진행 중인 행사**에서만 `POST /promotions/{id}/coupon-grants` 로 한다 — 만드는 화면에서는 받을 고객을 정할 수 없어 기능이 없는 것처럼 보인다.
- 요청(선택 필드, 없으면 지금처럼):
  - `CouponPolicy`(또는 PromotionInput)에 `recipients`: `{ accountIds: string[](최대 100 — grants 와 같은 한도), reason: string(1~200) }` — ADMIN 일 때만.
  - **승인되고 시작 시각이 되면 서버가 그 고객들에게 발급**(grants 와 같은 규칙 — 1인 한도·총 수량, 결과 ISSUED·SKIPPED_LIMIT·SOLD_OUT). 결과는 행사 상세에 `recipientResults[]`(또는 발급 기록)로.
  - 승인 심사(approval-service) 요약에 받을 고객 수가 보이면 좋겠다(심사자가 몇 명에게 나가는지 알게).
- 화면은 이 회신 전에도: 만들기에서 지정 발급을 고르면 "승인 뒤 진행 중일 때 행사 상세에서 발급" 안내, 발급 칸에서 고객 ID 대신 고객 찾기로 고르기를 먼저 넣는다(지금 계약으로).

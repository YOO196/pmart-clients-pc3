## R1. 로딩 화면(SPLASH)
**지금까지의 방식은 (b)였다.** 실행마다 뒤에서 `GET /storefront/banners?placement=SPLASH` 를 부르고, 이미지를 받아 기기에 저장해 두었다가 **다음 실행**의 로딩 화면에 썼다. 서버 목록이 비면 저장분을 지워 기본 화면으로 돌아갔고, 조회 실패는 "없음"으로 보지 않아 저장분을 그대로 두었다.

**실기기에서 바뀌지 않은 원인:** 저장분과 서버 값을 **bannerId 로만** 비교했다. 같은 `B-SPLASH` 에서 이미지만 바뀌면 새로 받지 않았다.

**바꾼 뒤 방식**
- **bannerId + 이미지 주소**(`imageUrl` = `/storefront/banner-images/{imageId}`)가 둘 다 같을 때만 그대로 둔다. 이미지만 바뀌어도 새로 받는다.
- 예전 앱이 저장한 것은 이미지 주소가 없어서 한 번 다시 받는다.
- 고객용 `Banner` 에는 `imageId` 필드가 없지만, `imageUrl` 에 imageId 가 들어 있어 그것으로 구분한다. 필드 추가는 필요 없다.
- 반영 시점은 그대로 **다음 실행부터**다. 사용자 결정(2026-11-21 "다음 실행부터")을 따랐다. 새 이미지를 받은 실행에서는 아직 예전 화면이고, 그다음 실행에서 새 이미지가 보인다.
- **그리는 방식: `contain`.** 그림을 잘리지 않게 다 보이고, 화면이 그림보다 길어 남는 위·아래는 **그림 맨 위 줄·맨 아래 줄의 평균 색**으로 채운다. 이 색은 이미지를 받을 때 한 번 계산해 같이 저장한다. 최소 1.5초 보이고, 누르면 바로 넘어가는 것은 그대로다.
- 기간: 고객용 `Banner` 응답에는 `startsAt`·`endsAt` 가 없다. 그래서 "서버가 지금 걸린 것만 준다"는 전제로, 목록에 없으면 저장분을 지운다. 저장분이 지워지기 전 한 실행 동안은 끝난 이미지가 보일 수 있다(다음 실행에서 지워진다). 이 한 실행도 막아야 하면 `Banner.endsAt` 를 응답에 넣어 달라 — 그러면 앱이 지난 것을 그리지 않겠다(선택).

## R2. 팝업(POPUP) — 반영함
- **창 폭은 화면 폭의 80%, 그림 칸은 4:5 고정, 그림은 칸 안에 `contain`.** 모서리는 둥글고, 아래에 [오늘 그만 보기 | 닫기]가 있다. 전에는 1:1 칸에 `cover` 였다.
- 그림을 누르면 `linkType`·`linkRef` 로 이동한다(SECTION 이면 그 테마 영역). 이전과 같다.
- **"오늘 그만 보기"·"닫기"(이번 실행 동안) 기억 단위는 bannerId + 이미지 주소(imageId)** 로 바꿨다. 같은 팝업이라도 이미지가 바뀌면 다시 보인다.

## R3. 팝업 "다시 보기"(선택) — 하지 않음
고객앱에 개발자 메뉴가 없다. 시험할 때는 다음 중 하나로 다시 볼 수 있다.
- 다음 날(서울 날짜)이 되면 "오늘 그만 보기" 기록이 저절로 무시된다.
- 팝업 이미지를 바꾸면 위 R2 규칙으로 바로 다시 뜬다.
- 휴대폰 설정 → 앱 → 저장공간 → 데이터 삭제(로그인도 지워진다).

## 확인
- `flutter analyze` 문제 없음. `splash_promo_test.dart`·`home_popup_test.dart` 19개가 통과했고, 그중 새로 쓴 시험은 5개다.
  - 이미지만 바뀌면 다시 받기
  - 예전 저장분 다시 받기
  - contain·가장자리 색
  - 받을 때 가장자리 색 계산
  - 팝업 80%·4:5·contain, 이미지 바뀌면 다시 뜨기
- 실기기 확인은 새 APK 설치 뒤다. 로딩 화면은 새 이미지를 받는 실행 한 번이 지나고 **그다음 실행**에서 바뀐다.

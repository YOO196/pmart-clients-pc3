## BR-87. 0건일 때 비슷한 상품
- 지금: 원래 검색어 0건이고 교정어도 없으면 결과 0건(`items` 빔) → 앱은 "검색 결과가 없어요"만. 초안 16 B-3 은 띠 "검색어와 비슷한 결과를 찾아봤어요." + "이런 상품은 어때요?" 2열.
- 요청 R1: `GET /search/products` 첫 쪽이 0건이면 `similarItems: SearchHit[]`(최대 N개, 예 20) — 비슷한 상품(자모·글자 유사, 같은 뜻 카테고리 인기 등 서버 판단). 0건이 아니면 비거나 없음. 카드 값은 `items` 와 같은 `SearchHit`(가격·availability·할인 포함).
- 앱: `similarItems` 가 있으면 띠 + "이런 상품은 어때요?" 2열, 없거나 비면 지금처럼(앱이 지어내지 않음). 다음 쪽 없음(한 번에).
- 질문 Q1: 이름을 `similarItems` 로 해도 될까요? 판단 규칙은 서버에 맡겨요.

## BR-88. 진짜 오타일 때만 correctedQuery·suggestedQuery
- 지금: "서울우유"(정상 상품명, 결과 적음)로 찾으면 `suggestedQuery: "우유"` → 앱 "혹시 우유를 찾으셨나요?". 사용자 "서울우유는 오타아닌데".
- 요청 R1: `correctedQuery`·`suggestedQuery` 는 검색어가 사전·상품명에 없는 오타로 볼 때만. 결과가 적다는 이유만으로 더 짧은(상위) 검색어를 제안하지 않기 — 원래 검색어가 상품명·브랜드에 그대로 있으면 제안 없음.
- 앱: 서버 값만 보이므로 앱 변경 없음(초안 16 B-2 "혹시 {q}를 찾으셨나요? {q}로 검색 ›" 띠는 값이 올 때만).

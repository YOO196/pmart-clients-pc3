# 회신·질문 — 오배송 "못 받았어요" 문의·채팅 안 선택: 고객앱 화면 설계(ADR-0086)

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (case-service R-16 — PC 2 구현, 계약 정리 PC 1 백엔드)
- 원 문서: `../pmart-backend/docs/handoff/clients/customer-app/2026-11-24-request-misdelivery-inquiry-choice.md`
- 상태: **화면 설계만**(계약 전 — 요청서 지시). 계약(case 버전·선택 API)이 나오면 구현한다. 아래 Q 에 답이 오면 설계를 고친다.

## 지금 앱에 있는 것
- 주문 상세 › 문의하기("무엇을 도와드릴까요?", 레퍼런스 9-2 3-1) — 배송 신고 줄이 상태별로: 진행 중 = 늦어요, 일부 도착 = 늦어요·다른 곳에 배달, 배달 완료 = **상품을 받지 못했어요(NOT_RECEIVED)**·다른 곳에 배달. 누르면 문의 남기기 화면 → `POST /inquiries`(DELIVERY + deliveryIssue, orderId, deliveryId 를 알면 함께).
- 배송 조회의 전달 사진(`GET` delivery proof), 내 문의 내역·문의 상세(타임라인 — 상담원 답이 시간 순).

## 설계
### D1 진입 — "상품을 못 받았어요"
- 주문 상태 **배달 중·일부 도착·배달 완료** 모두에 "상품을 받지 못했어요"를 둔다(지금은 배달 완료만). 오배송 사건으로 열릴지(전달 완료 배송인지)는 서버가 정한다 — 앱은 미리 거르지 않는다.
- 누르면 바로 접수하지 않고 **확인 화면**(레퍼런스 9-2 3-3 "입력한 주소로 배달이 오지 않았나요?"):
  - 주문 배송지 주소 카드, 그 배송의 **전달 사진**(있으면 — 크게 보기). 사진이 없거나 못 읽으면 그 칸을 숨긴다.
  - 아래 고정 [못 받았어요, 문의 남기기](주 버튼). 레퍼런스의 [라이더님께 통화 요청]·[실시간 채팅상담]은 계약에 없어 넣지 않는다(고객센터 실시간 상담은 없음 — 2026-11-09 결정).
  - 주 버튼 → `POST /inquiries` `category: DELIVERY`, `deliveryIssue: NOT_RECEIVED`, `orderId`, `deliveryId`(그 주문의 전달 완료 고객 배송 — Q2), 본문은 앱 기본 문구(Q3). Idempotency-Key 는 이 화면 한 번 누름 단위, 결과 불명이면 같은 키로 다시.
  - 접수되면 그 문의 상세로 간다.

### D2 문의 상세 — 선택 카드
- case 가 넣은 **선택 메시지**를 타임라인 안 카드로: 제목 "어떻게 해 드릴까요?", 버튼 두 개 [다시 보내기] [취소·환불], 아래 줄 "**M월 d일 HH:mm까지** 고르지 않으면 자동으로 환불돼요 · 남은 시간 N시간 M분"(서버 기한 `deadlineAt` 기준, 1분마다 다시 셈. 기한이 지났는데 아직 결과가 없으면 "자동 환불을 처리하고 있어요").
- 누르면 확인 창(다시 보내기: "같은 상품을 다시 보내 드려요" / 취소·환불: "결제하신 금액을 돌려드려요 — 금액은 서버 값"), [확인] → 선택 API **한 번**(Idempotency-Key 를 그 선택에 묶어 둠 — 재시도·앱 다시 켬도 같은 키). 보내는 동안 두 버튼 모두 막음.
- 결과: 서버가 확정한 것만 확정으로. ACCEPTED 는 "요청을 받았어요 — 처리 중", 결과 불명은 짝 조회로 해소, 거절(기한 지남·이미 고름 등)은 code 별 안내 후 문의를 다시 읽는다.
- 고른 뒤·자동 환불 뒤에는 버튼 대신 결과 문장: "다시 보내기를 골랐어요" / "취소·환불을 골랐어요" / "기한이 지나 자동으로 환불했어요"(`autoResolved`). 상담원이 대신 고른 경우 "상담원이 ○○로 처리했어요"(Q4).
- 문의 목록 카드에도 "선택을 기다려요 · 남은 시간"을 보인다(Q5 — 목록에 필요한 값).

### D3 진행·종결 표시
- 다시 보내기: 주문 상세 배송 조회에 재발송 배송이 생기면 그대로 보이고, 전달되면 주문 "배달 완료". 환불: 주문 상세 처리 내역(클레임)·환불 금액은 서버 값.
- 주문이 "일부 도착·배달 중"에 남지 않는 것은 서버(0ae3a416)에 맡긴다 — 앱은 주문 상태를 그대로 보인다.
- 선택·결과 알림(푸시·알림함)은 지금 있는 알림으로 받고 누르면 그 문의 상세로(Q6).

## 질문
- Q1 선택 메시지 모양: 문의 상세(`GET /inquiries/{id}`)의 메시지·타임라인에 어떤 종류·필드로 오나요? 앱이 쓸 것: 선택지(RESHIP·REFUND), `deadlineAt`, 고른 값·고른 주체(고객/상담원/자동), `autoResolved`, 상태(대기·처리 중·확정). 지금 고객 문의는 상담원 답 타임라인이고 "고객 채팅"은 라이더 대화만(0.21.0) — 고객 문의에 채팅 메시지를 새로 두는지, 문의 상세 필드로 두는지.
- Q2 `deliveryId`: 앱은 주문 상세에 배송 ID 가 없고 배송 조회(트래킹)에서 배송 목록을 읽는다. 전달 완료 배송을 앱이 골라 보내야 하나요, 아니면 orderId 만 주면 서버가 고르나요(재발송까지 여러 배송일 때)?
- Q3 본문(`content`) 필수·최소 길이 — 확인 화면에서 바로 접수하려면 앱 기본 문구를 넣어도 되는지, 서버가 비어 있어도 받는지.
- Q4 상담원이 대신 고른 것·자동 환불을 고객 화면에서 구분할 값.
- Q5 문의 목록(`GET /inquiries`)에서 "선택 대기·기한"을 보일 값이 오는지.
- Q6 선택 메시지가 생길 때·결과가 정해질 때 고객 알림(종류 코드)이 오는지.
- Q7 선택 API 응답(CommandResponse 4값인지, 짝 조회 경로)과 거절 code(기한 지남·이미 고름·사건 없음).

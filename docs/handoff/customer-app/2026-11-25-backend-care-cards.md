- 받는 백엔드 영역: platform (storefront) · 백오피스(PC 2) 입력 화면
- 계기: 사용자 2026-11-25 "이미지가 없어 — 백오피스에서 관리하게 만들어줘".
- 레퍼런스: `docs/customer-app-design/4. 상품페이지, 상품 아이콘 분류/5. 상품페이지 전체 (2026-11-25 사용자 제공).jpg` 중 "우리동네 B마트, 이렇게 관리해요"(앱은 "우리동네 PMart").

## 지금 앱
- 상품페이지 상품설명 아래 구획. 제목 "우리동네 PMart, 이렇게 관리해요" + 옆으로 넘기는 카드(268.6×245dp — 위 그림 152dp, 제목 굵게, 설명 두 줄).
- 카드 2장(사전 품질 검수 / 온도 맞춤 보관) 문구를 앱에 고정해 두었고 그림이 없다(회색 + 흐린 "PMart").

## 요청
- R1 고객 조회(토큰 없이): 예 `GET /storefront/care-cards` → `{title, items: [{cardId, imageUrl, title, body, sortOrder}]}`. 모든 상품 공통(센터별·카테고리별이 필요하면 `mfcId`·`categoryId` 선택). 게시된 것만, 정렬 순. 없으면 빈 목록 → 앱은 구획을 뺀다.
  - `body` 는 줄바꿈(`\n`)을 그대로 보인다(레퍼런스 두 줄).
  - 그림은 배너처럼 이미지 ID 마다 불변·`?w=` 축소본(BR-99 와 같은 방식)이면 좋다. 카드 그림 칸 268.6×152dp(약 1.77:1).
- R2 백오피스 편성: 카드 추가·수정·순서·게시/내림, 그림 올리기(규격 안내 — 약 1.77:1), 구획 제목. 바꾸면 승인 흐름이 필요한지는 배너 편성과 같게.
- 이름(제목·카드 경로)은 백엔드가 정해 주세요.

## 앱 처리
- 계약 전: 지금 고정 카드 2장(그림 없음). 계약이 나오면 서버 값으로 바꾸고, 목록이 비면 구획을 뺀다(지어내지 않는다).

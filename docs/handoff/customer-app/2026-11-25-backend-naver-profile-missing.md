# 요청 — BR-103 네이버 첫 가입 뒤 이름·이메일·프로필 사진이 비어 있음(긴급)

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (auth-service · customer-service)
- 계기: 사용자 2026-11-25 실기기(갤럭시 A53) — "네이버로 로그인했는데 이름·프로필·이메일 다 안 받는다", "처음 소셜 로그인 이후 다시 로그인해야 이메일이 뜬다", "이름이랑 프로필은 여전히 안 된다".
- 네이버 개발자센터 제공 정보(사용자 캡처): 회원이름 **필수**, 연락처 이메일 주소 **필수**, 프로필 사진 **추가**.

## 증상
1. 네이버로 **처음 가입**(교환 → 동의 → 휴대폰 확인 → 회원)한 뒤 `GET /me` 에 이름·이메일·사진이 없다(내 정보 "이름 없음"·"이메일 정보 없음"·기본 아바타).
2. 다시 네이버로 로그인하면 이메일은 채워진다. 이름·사진은 그래도 없다(이름은 앱 표시 결함도 있었다 — 아래 "앱 쪽").

## 앱이 보내는 것(확인함)
- `POST /auth/naver-token-exchanges` 응답의 `profileImageUrl` 을 받아 `social-logins`·`completions`·`identity-verifications/…/confirmations` 세 곳 모두에 `profileImageUrl` 로 그대로 넣는다(auth 0.8.0). 이름·이메일은 앱이 보내지 않는다(서버가 교환 때 네이버 프로필 API 에서 받아 sub 에 10분 묶음 — BR-77·V9).

## 코드로 본 의심(확인 부탁)
- Q1 첫 가입은 `publishAuthenticated` 가 **휴대폰 확인 완료 때** 한 번 나간다. 그때 `naverEmails.takeProfile(sub)` 의 10분 보관이 이미 지났거나(동의 + 문자 확인이 10분을 넘기기 쉬움) 앞 단계에서 비워졌으면 이름·이메일이 빠진다 → **가입이 끝날 때까지(원인증 요청 행에) 보관**해 달라.
- Q2 이름: 교환 때 `profile.name()` 이 비었는지(네이버 응답 `response.name`), 사건 `name` → customer `name` 에 들어가는지. 다시 로그인해도 비는 이유.
- Q3 사진: 교환 응답에 `profileImageUrl` 이 실제로 실렸는지(네이버 `profile_image` — 추가 항목이라 사용자가 동의 화면에서 껐을 수도), `ProviderPictureRules.pick`·customer 사본(`/me/profile-image`)까지 가는지.
- 값 자체는 남기지 말고 **어느 단계에서 어떤 항목이 있었는지(있음/없음)** 만 로그로 확인해 주세요.

## 요청
- R1 첫 가입 한 번에 이름·이메일·사진이 들어가게(다시 로그인 없이).
- R2 Q1~Q3 확인 결과 회신.

## 앱 쪽
- 내 정보 "이름" 줄이 앱에서 정한 이름(nickname)만 보고 서버 `name` 을 안 봐서 "이름 없음"이었다 → nickname 이 없으면 `name` 을 보이게 고침(2026-11-25).

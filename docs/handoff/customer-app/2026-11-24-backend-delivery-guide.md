# 요청 — BR-96 홈 배달 안내 값(최소 주문·배달팁 구간·운영 시간)을 `GET /delivery-options` 에

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (order-service `GET /delivery-options` — 정책 값은 설정 저장소)
- 계기: 사용자 2026-11-24 새 홈 UI — "지금 주문하면 이렇게 받아요" 대신 **"알뜰배달 29~44분 · 최소주문 15,000원 [배달안내]"**, 아래 **"30,000원부터 배달팁 0원 ›"**, 누르면 **배달 안내 시트**(24시간 주문 가능·배달 운영 시간·방식별 예상시간과 배달팁 구간).

## 지금 계약(order-service `DeliveryOption`)으로 되는 것 / 안 되는 것
- 됨: 방식·가능 여부·예상시간(eta)·기본 배달팁(`deliveryTip.base`)·가장 빠른 예약 슬롯.
- 안 됨:
  - 최소 주문 상품액 — 주문 초안 `Quote.minOrderAmount`·장바구니 `minOrderAmount` 에만 있다. 앱은 지금 장바구니 값으로 대신 보인다(장바구니를 못 읽으면 빠짐).
  - 배달팁 구간(예: 30,000원 이상 0원 / 15,000원 이상 3,000원) — 무료 사유 enum `OVER_30000` 만 있고 **금액 기준값이 없다**. 앱이 enum 이름에서 30,000 을 꺼내 쓰지 않는다.
  - 실제 배송 운영 시간(지금 00:00~08:00 은 NIGHT_TIME — 시각 값이 없다).

## 요청
- R1 `DeliveryOption` 에 `minOrderAmount`(Money, 정책 미설정이면 PolicyValue NOT_SET — 0 으로 보내지 않기).
- R2 `DeliveryOption.deliveryTip.tiers[]` = `{fromAmount, tip}` 높은 금액부터(첫 구매 무료 같은 개인 사유는 빼고 상품액 구간만). 방식마다 다를 수 있게 방식 안에.
- R3 `DeliveryOptions.serviceHours` = `{start: "08:00", end: "24:00"}`(서울, 실제 배송하는 시간 — 주문은 24시간 받고 그 밖은 예약만이라는 지금 규칙 그대로).
- 다 선택 필드(없으면 앱은 그 줄을 뺀다). 값은 설정 저장소 정책 값 그대로.

## 앱이 지금 한 것(목)
- 도메인 `DeliveryOption.minOrderAmount`·`tipTiers`·`serviceHours`(`// BR-96`), 목은 최소 15,000·30,000 이상 0원·기본 팁(한집 4,000 / 알뜰 3,000)·08:00~24:00.
- 실서버: 최소 주문은 장바구니 값, "○원부터 배달팁 0원" 줄은 숨김, 시트는 방식마다 "기본 배달팁" 한 줄·운영 시간 줄 없음.
- 같은 화면의 쿠폰 줄·"할인받고 주문해요" 시트는 promotion 계약(`GET /coupon-campaigns`·받기)으로 된다 — 요청 없음. "고객님을 위해 고른 혜택"(개인 추천)·"적용 상품 보기"·"주문당 1개까지 중복사용 가능" 은 계약에 없어 넣지 않았다(필요하면 따로 요청).

# 요청 — BR-74 네이버 로그인마다 정보 제공 동의(권한 선택) 화면이 다시 나오게

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (auth-service)
- 이어지는 것: ADR-0078(네이버 인가 코드 서버 교환, auth 0.10.x), BR-70(교환 때 프로필 사진)
- 계기: 사용자 2026-11-20 "네이버 아이디, 비밀번호를 매번 다시 입력하게 하고 권한 선택 화면 다시 보이게 해줘"

## 앱이 한 것
- 인가 요청(`nid.naver.com/oauth2/authorize`)에 `auth_type=reauthenticate` — 브라우저에 네이버 로그인이 남아 있어도 아이디·비밀번호를 다시 받는다.
- 앞서 붙인 `auth_type=reprompt` 는 실기기에서 바로 로그인됐다. 우리가 아는 한 `reprompt` 는 **전에 거부한** 항목만 다시 묻는 값이라, 다 동의했던 계정은 동의 화면이 다시 나오지 않는다. (네이버 개발자 문서를 이쪽에서 읽지 못해 확인은 못 했다 — 맞는지 봐 달라.)

## 왜 서버가 해야 하나
- 이미 동의한 앱에 대해 네이버는 동의 화면을 다시 띄우지 않는다. 다시 띄우려면 네이버 쪽 **앱 연결(토큰)을 끊어야** 한다 — 네이버 토큰 삭제 요청(`grant_type=delete`, client secret·access token 필요).
- client secret 은 서버에만 있고(ADR-0078), access token 도 교환 때 서버만 받았다가 버린다. 앱은 할 수 없다.

## 부탁
- **R1.** `POST /auth/naver-token-exchanges` 에서 id_token 을 받은 뒤(BR-70 프로필 사진을 읽은 **뒤**) 그 access token 으로 네이버 연결을 끊어 달라. 다음 네이버 로그인에서 동의 화면이 다시 나온다.
  - 끊기에 실패해도 교환은 성공으로(로그인을 막지 않음) — 그 경우 다음 로그인에 동의 화면이 안 나올 수 있다.
- **R2. 꼭 확인**: 연결을 끊었다 다시 동의해도 네이버가 주는 사용자 식별값(id_token `sub`)이 **같은지**. 달라지면 로그인할 때마다 새 계정이 생긴다 — 그러면 R1 은 하지 말고 알려 달라.
- **R3.** 매 로그인마다 끊을지, 가입을 끝내지 않은 계정(BR-72)일 때만 끊을지 정해 달라. 사용자 말은 "매번"이다. 다만 교환 시점에는 아직 계정이 정해지지 않아(교환 → 로그인 순서) "가입 중일 때만"은 로그인 단계에서 끊어야 할 수 있다.
- **R4.** 탈퇴 재인증의 교환에서도 끊는지(탈퇴 완료면 끊는 게 맞아 보인다).
- **R5.** 끊기 요청에 쓴 access token 은 지금처럼 저장·로그하지 않는다.

## 앱
- 바꿀 것 없다(서버가 끊으면 다음 인가 요청에서 네이버가 동의 화면을 띄운다). 회신 뒤 실기기로 "로그인 → 앱 나감 → 다시 네이버 로그인 → 아이디·비밀번호 + 동의 화면" 확인.

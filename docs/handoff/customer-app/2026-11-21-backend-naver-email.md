# 요청 — 네이버 로그인 계정에도 이메일 (BR-77)

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (auth-service — 고객 소셜 로그인·네이버 토큰 교환)
- 작성: pmart-clients, 2026-11-21 — 사용자 실기기 확인 "로그인시 이메일 현재 구글만 보임, 카카오톡 안보임 (네이버도 안보일 가능성 있음)", "네이버는 사용 api로 있던데", "요청서 써서 보내"
- 기준 계약: `auth-service.yaml` 0.11.0(`POST /auth/naver-token-exchanges`), `customer-service.yaml` 고객 프로필 `email`("로그인 제공자가 준 이메일. 없을 수 있다")

## 지금 상황(앱이 확인한 것)
- 고객앱 내 정보·마이의 이메일은 서버 프로필 `email` 을 그대로 보인다. 서버는 로그인 때 **ID 토큰의 `email` 클레임**으로 채운다(`IdTokenVerifier` — 읽기 전용으로 확인).
- 네이버 OIDC 설정(`https://nid.naver.com/.well-known/openid-configuration`, 2026-11-21 직접 확인): `scopes_supported` = `openid, profile`, `claims_supported` = `iss, sub, aud, exp, iat, jti, azp, nonce` — **네이버 ID 토큰에는 이메일이 없다.** 앱이 인가 요청 scope 를 늘려도 받을 수 없다.
- 서버는 이미 교환 직후 네이버 access token 으로 **회원 프로필 API `GET https://openapi.naver.com/v1/nid/me`** 를 한 번 불러 `profileImageUrl` 을 준다(auth 0.10.1, BR-70). 같은 응답의 `response.email` 에 이메일이 있다(네이버 개발자센터 "제공 정보 — 이메일 주소"를 켜고 고객이 동의했을 때).
- (참고) 카카오는 콘솔 비즈 앱 전환 + 동의항목 "카카오계정(이메일)"을 켜면 ID 토큰에 `email` 이 들어온다 — 서버 변경 없이 사용자 콘솔 작업으로 진행 중.

## 요청
- **R1. 네이버 계정 이메일 저장** — 교환 때 부르는 `/v1/nid/me` 응답의 `email` 을 그 네이버 계정(이 교환의 id_token `sub`)의 이메일로 써 주세요. 로그인·가입 완료 뒤 고객 프로필 `email` 에 보이면 된다.
  - **앱이 보낸 값이 아니라 서버가 네이버에서 직접 받은 값**으로 저장해 주세요(앱이 넘기는 이메일은 바꿔치기할 수 있다). 그래서 교환 응답에 `email` 을 실어 앱이 로그인 본문으로 다시 보내는 방식은 권하지 않는다 — 서버 안에서 교환 결과와 로그인을 잇는 방식(예: 교환 때 sub→email 을 짧게 보관했다가 그 id_token 으로 로그인할 때 쓰기)을 정해 주세요.
  - `emailVerified` 는 네이버가 확인 여부를 주지 않으면 null(또는 false) — 어떻게 둘지 알려 주세요.
- **R2. 없거나 실패하면** — 고객이 이메일 제공에 동의하지 않았거나 프로필 API 가 실패·시간 초과면 이메일 없이 로그인은 지금처럼 성공(지금 `profileImageUrl` 과 같은 규칙). 이미 저장된 이메일을 빈 값으로 지우지는 않기를 제안.
- **R3. 이미 가입한 네이버 계정** — 다음 로그인 때 R1 로 채워지면 충분한지, 따로 옮길 것이 있는지 알려 주세요.
- **R4. 로그·보관** — access token·이메일 원문을 로그에 남기지 않기(지금 토큰 규칙과 같게).

## 앱이 할 것
- 없음 — 서버 프로필 `email` 을 지금처럼 보인다. 서버 반영 뒤 실기기 네이버 로그인으로 내 정보 이메일을 확인한다.
- 사용자 작업: 네이버 개발자센터 → 내 애플리케이션 → API 설정 → 사용 API "네이버 로그인" → 제공 정보에서 **이메일 주소** 켜기.

# 고객앱 처음 실행 약관 — 위치 기반 서비스 약관·로그인 전 동의 기록 (BR-59)

보낸 앱: customer-app (PC 1)
받는 백엔드 영역: platform (customer-service·auth)
날짜: 2026-11-19

## 배경
- 사용자 결정(2026-11-19): 고객앱을 처음 켜면 레퍼런스(배달 앱 캡처 2-1)처럼 **환영·약관 화면**을 먼저 보이고, 그다음 로그인/둘러보기 → 배달 주소 등록(필수) → 홈으로 간다.
- 환영·약관 화면 항목: 전체동의 / **위치 기반 서비스 약관 동의(필수)** / **마케팅 정보 앱 푸시 알림 수신 동의(선택)**. 필수를 골라야 "시작하기"가 눌린다.
- 이 시점의 고객은 **로그인 전(비회원)** 이다. 회원 약관(이용약관·개인정보·만 14세·마케팅)은 지금처럼 로그인 때 AUTH_CONSENT 로 서버가 묻는다 — 이 요청과 겹치지 않게 하고 싶다.

## 계약 공백
1. customer-service `consentType` 은 `TERMS_OF_SERVICE`·`PRIVACY_POLICY`·`AGE_OVER_14`·`MARKETING` 뿐이다. **위치 기반 서비스 약관** 유형이 없다.
2. 로그인 전(기기·비회원 토큰) 동의를 남길 경로가 없다. 동의 변경(`/me/consent-changes`)은 회원 토큰이 있어야 한다.
3. 마케팅 앱 푸시 수신 동의의 **처리 결과(전송자·수신동의 일시·처리 내용)** 를 받을 응답이 없다. 레퍼런스 2-2 는 동의 직후 "수신동의 처리완료" 안내 창을 띄운다(정보통신망법 수신동의 결과 고지로 보임).
4. 약관 본문(항목 옆 `>` 로 펼쳐 보기)을 받을 경로가 없다.

## 요청
- **R1** 위치 기반 서비스 약관 동의 유형과 현행 버전(`TYPE:version` 형식, 기존 동의와 같게).
- **R2** 로그인 전 동의 기록 경로 — 기기 ID 또는 비회원 토큰(typ=GUEST)으로 위치 약관·마케팅 푸시 동의를 남기고, 같은 기기에서 로그인·가입하면 회원 동의로 옮기는(또는 다시 묻는) 방식. 둘 중 무엇이 맞는지 정해 주세요.
- **R3** 마케팅 푸시 수신 동의 결과 응답 — 서버가 기록한 일시(UTC)와 처리 결과. 앱은 이 응답을 받은 경우에만 "처리완료" 안내를 띄운다.
- **R4** 약관 본문 조회(유형·버전별 제목·본문 또는 본문 주소).
- **질문** 위치 기반 서비스 약관을 로그인 전에 받는 것이 업무 문서상 맞는지, 아니면 회원 동의(AUTH_CONSENT)의 필수 항목으로 넣어야 하는지.

## 지금 클라이언트가 하는 것 (계약이 생기기 전)
- `apps/customer_app/lib/features/start` — 동의를 **이 기기 보안 저장소에만** 둔다(위치 동의·마케팅 선택·시각). 서버에 보내지 않는다.
- 서버가 받지 않았으므로 "수신동의 처리완료" 안내 창은 띄우지 않고, 약관 `>` 도 넣지 않았다.
- 계약이 생기면 저장해 둔 값을 보내고, R3 응답을 받은 뒤에만 처리완료를 보인다.
- 처음 실행의 주소 등록은 기존 계약만 쓴다(비회원 `POST/GET /guest-delivery-addresses`, 회원 `/me/addresses`) — 이 부분은 요청 없음.

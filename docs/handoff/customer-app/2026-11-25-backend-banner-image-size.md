# 요청 — BR-99 배너 그림을 앱 화면 크기로 줄여서 주기

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (storefront `GET /storefront/banner-images/{imageId}`)
- 계기: 사용자 2026-11-24 "상품 페이지·홈·주문내역·리뷰 로딩 시간이 너무 길다" → 원인 측정 중 확인.

## 잰 것(2026-11-24, 이 PC → LAN 게이트웨이 `https://192.168.0.40:8443`)
- API 응답은 빠르다: 홈 0.07~0.09초, 리뷰 0.02~0.04초, 카테고리 트리·배너 목록 약 0.02초.
- 상품 사진(content-images, `?width=` 축소본)은 장당 약 50KB·0.02~0.03초.
- **홈 배너 그림은 장당 약 2.1~2.3MB PNG**(예 `BIMG-40f4e8c3-…` 2,313,526B, `BIMG-850983d5-…` 2,229,461B, `BIMG-64d9ddfe-…` 2,103,108B).
  - `?width=720`·`?width=1080` 을 붙여도 같은 원본이 온다(축소본 없음).
  - 폰 Wi‑Fi 에서는 배너 몇 장만으로 받기·풀기에 1초 안팎 — 홈이 늦게 뜨는 주원인으로 본다. 앱은 이미 화면 폭만큼만 디코딩(`cacheWidth`)하지만 받는 양은 줄일 수 없다.

## 요청
- R1 `GET /storefront/banner-images/{imageId}` 에 `width` 쿼리(content-images 와 같은 방식 — 예 360·720·1080, 가장 가까운 단계로) — 앱은 화면 폭 × 화소 비율을 보낸다.
- R2 축소본은 JPEG 또는 WebP(사진 배너는 PNG 가 아주 크다). 원본은 그대로 보관.
- R3 지금 올라간 배너(LAN 시드 포함)도 축소본이 나오게. 올릴 때 규격(`banner-image-specs` maxBytes 5MB)은 그대로 두되, 내려줄 때 줄인다.
- Q1 캐시 헤더(1년 immutable)는 축소본에도 같은지.

## 앱
- 축소본이 생기면 배너 그림 주소에 `width` 를 붙인다(상품 사진의 `withImageWidth` 와 같은 처리). 그 전까지 앱 변경 없음.
- 기기 로딩 시간 측정(profile 빌드, 홈·상품 상세·주문내역·리뷰)은 따로 한다 — 결과에 따라 앱 쪽 개선을 이어서 적는다.

# 요청 — BR-72 가입을 끝내지 않고 나갔으면 다음 로그인 때 동의부터 다시

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (auth-service·customer-service)
- 이어지는 것: `../pmart-backend/docs/handoff/clients/customer-app/2026-11-20-reply-br64-phone-identity.md`(ADR-0074 — 동의 → 휴대폰 확인 → 회원)
- 계기: 사용자 2026-11-20 "네이버 가입이 안 된 건데 저번에 동의한 내역이 남아 있는지 넘어가는데" → "처음부터 다시 받고 싶어"

## 지금 동작(auth-service `CustomerSocialLoginService` 로 확인)
1. 처음 소셜 로그인 → 계정·제공자 연결을 만든다(회원이 된 적 없음) → `AUTH_CONSENT`.
2. 동의 화면에서 동의(`/completions`) → 그 계정에 동의 저장 → `AUTH_IDENTITY`.
3. 휴대폰 확인을 끝내지 않고 앱을 나감 — 계정·연결·동의가 그대로 남는다.
4. 같은 소셜로 다시 로그인 → 필수 동의가 이미 충족이라 **동의 화면 없이** 바로 `AUTH_IDENTITY`.

가입 중 계정을 지우는 경우는 휴대폰 확인이 409(`IDENTITY_ALREADY_REGISTERED`·`IDENTITY_REJOIN_BLOCKED`)로 막혔을 때뿐이다(`discardIfNeverMember`).

## 사용자 결정
가입이 끝나지 않았으면(회원이 된 적 없는 계정) **다음 로그인은 처음부터** — 동의 화면부터 다시 받는다.

## 부탁
- **R1.** 회원이 된 적 없는 계정(`everMember = false`)으로 로그인하면 전에 저장한 동의와 상관없이 `AUTH_CONSENT` 부터 시작하게 해 달라.
  - 방법은 맡긴다 — 예: 로그인 때 그 계정·연결·동의를 버리고 새로 만들기(409 때와 같은 `discardIfNeverMember`), 또는 동의를 남기되 가입 중에는 충족으로 보지 않기.
- **R2.** 그때 전에 저장된 동의 기록(필수·선택)을 어떻게 둘지 정해 달라 — 지우는지, 남기고 새 결정으로 덮는지. 선택 항목(마케팅)은 고객이 다시 고른 값이 최종이어야 한다.
- **R3.** 처음 실행 화면에서 받은 기기 동의(마케팅·위치)는 지금처럼 로그인 때 계정으로 옮겨져 선택 항목에서 빠지는지, 가입을 다시 시작할 때도 같은지 알려 달라(앱은 서버가 준 `optionalConsents` 만 그린다).
- **R4.** 진행 중이던 휴대폰 확인(OCTOMO 숫자)이 있으면 같이 버려지는지 — 월 한도에 영향이 있으면 알려 달라.
- 이미 회원인 계정의 재동의(약관 새 판)·기존 회원의 휴대폰 확인은 지금 그대로.

## 앱
- 바꿀 것 없다 — 서버가 준 단계(`AUTH_CONSENT` → `AUTH_IDENTITY`)를 그대로 그린다. 서버가 바뀌면 실기기로 확인한다.

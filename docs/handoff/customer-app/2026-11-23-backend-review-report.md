# 요청 — BR-90 리뷰 신고하기(고객) + 운영자 확인

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (review-service, 지금 0.6.1)
- 계기: 사용자 2026-11-23 "나 리뷰에 신고하기버튼있었던것같은데" → 레퍼런스(4. 상품페이지 › "4. 상품리뷰 전체 보기 - 리뷰 목록에서 보이는 전문": 리뷰 카드 아래 "2026.09.24 | 신고하기")에는 있으나 계약에 없어 앱에 넣지 않았음. review 계약 설명 "운영자 숨김·신고는 아직 없다(사용자 결정 — 정책 승인 전)" → 사용자가 아래 정책을 정함(2026-11-23 "응 진행해줘", 추천안 그대로).

## 정책(사용자 결정 2026-11-23)
1. 신고는 **회원만**(비회원은 버튼 대신 로그인 안내).
2. 사유: 욕설·비방 / 광고·홍보 / 상품과 관계없는 내용 / 개인정보 노출 / 기타(직접 입력, 기타일 때만 글 — 길이 상한은 서버 값).
3. **한 사람당 한 리뷰에 한 번**. 다시 누르면 "이미 신고한 리뷰예요".
4. 신고만으로 숨기지 않는다 — **운영자가 확인한 뒤 숨김**(숨기면 상품 리뷰 목록·집계에서 빠짐. 집계 반영 방식은 서버 판단).
5. **자기 리뷰는 신고할 수 없다**(버튼 없음, 서버도 거절).
6. 처리 결과를 신고자에게 **알리지 않는다**.

## 요청 R1 — 고객 API
- `POST /reviews/{reviewId}/reports` (회원, `Idempotency-Key`): 본문 `{reason: ABUSE|AD|IRRELEVANT|PRIVACY|OTHER, detail?: string}` → 접수 결과. 오류 code 예: 이미 신고(중복), 자기 리뷰, 없는/숨긴 리뷰, OTHER 인데 detail 없음 — 이름은 서버가 정해 주세요.
- 상품 리뷰 목록(`GET /product-contents/{id}/reviews` 쪽 리뷰 카드)에 회원 요청이면 `reportedByMe: boolean`(이미 신고했으면 버튼 대신 "신고함" 표시용)·`mine: boolean`(자기 리뷰 — 버튼 숨김용) — 없으면 앱은 버튼을 보이고 서버 거절 code 로 안내한다. 넣을지 서버 판단.
- 질문 Q1: 신고 접수 응답이 바로 확정(APPLIED)인지, 비동기(ACCEPTED)인지 — 앱은 "신고가 접수됐어요"를 확정일 때만 보인다.

## 요청 R2 — 운영자(통합 백오피스, PC 2 담당)
- 신고 목록(리뷰·사유·건수·상태)·확인 처리(숨김 / 문제없음) API. 화면은 백오피스(PC 2)가 만든다 — 계약이 나오면 PC 2 에 알려 주세요.

## 앱
- 상품 리뷰 카드 날짜 옆 "| 신고하기"(레퍼런스 모양) → 사유 고르기 시트 → 보내기. 비회원은 로그인 안내, 자기 리뷰는 버튼 없음. 결과 불명은 같은 키로 다시(멱등).

# 요청 — BR-80 내 정보 프로필 사진 바꾸기(올리기·기본으로·로그인 계정 사진으로 되돌리기)

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (customer-service)
- 이어지는 것: ADR-0024(로그인 제공자 프로필 사진 사본 `GET /me/profile-image`), customer 0.14.0
- 계기: 사용자 2026-11-21 "프로필 이미지도 편집되게 만들어줘"(초안 `../고객앱 ui/02_내정보/my_info_v2_photo.html` G안) → "백엔드 요청 + 지금은 빼기"

## 지금
- 고객앱 내 정보는 로그인 계정 사진 사본(`GET /me/profile-image?v=…`, 본인 토큰)만 보인다. 로그인할 때마다 서버가 최신으로 바꾼다.
- 고객이 직접 사진을 고르거나 지우는 API 가 없어, 앱은 카메라 표시·사진 바꾸기를 넣지 않았다(2026-11-21 내 정보 F안 반영).

## 부탁
- **R1. 직접 고른 사진 올리기**: 본인 토큰, `Idempotency-Key`. 앱은 정사각형으로 자르고 줄여(예: 512px, JPEG) 보낸다. 형식·크기 상한은 서버가 정해 계약에 적어 달라. 결과는 `CommandResponse`(APPLIED 면 새 `profileImageUrl`).
- **R2. 기본 이미지로**(사진 없음): 직접 고른 사진·로그인 계정 사진 모두 보이지 않게.
- **R3. 로그인 계정 사진으로 되돌리기**: 직접 고른 사진을 지우고 다시 로그인 제공자 사진 사본을 쓴다.
- **R4. 규칙**: 직접 고른 사진(R1)이나 기본(R2)을 고른 뒤에는 로그인해도 제공자 사진으로 덮지 않는다. 지금 어느 쪽인지(`photoSource`: PROVIDER·CUSTOM·NONE 같은 값)를 `GET /me` 에 실어 달라 — 앱이 시트에서 [로그인 계정 사진으로 되돌리기]를 보일지 정한다.
- **R5.** 사진 조회는 지금처럼 `profileImageUrl`(`?v=` 바뀌면 새로 받음). 사진·주소를 로그에 남기지 않는다.

## 앱이 할 일(계약이 생기면)
- 내 정보 가운데 사진에 카메라 표시 → 시트(앨범에서 고르기 / 사진 찍기 / 로그인 계정 사진으로 되돌리기 / 기본 이미지) → 원형 맞추기 → 서버 확정 뒤 "프로필 사진을 바꿨어요". 카메라·사진 권한 안내.
- 그 전에는 넣지 않는다(목에서만 흉내 내지도 않음 — 사용자 결정).

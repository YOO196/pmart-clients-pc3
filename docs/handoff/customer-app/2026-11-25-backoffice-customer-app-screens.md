# 요청 — 고객앱 새 화면에 필요한 백오피스 입력·처리 화면 (BR-95·96·99·100)

- 보낸 앱: customer-app (PC 1)
- 받는 쪽: **backoffice (PC 2 — `web/backoffice`)**. API 는 백엔드가 만든다 — 같은 내용을 백엔드 요청서에 적었다(아래 "백엔드 요청서"). 백엔드 계약이 나오면 이 화면을 붙여 주세요.
- 계기: 사용자 2026-11-25 — 고객앱 상품페이지·리뷰를 레퍼런스대로 만들고(앱만으로 되는 부분은 끝냄), "백엔드/백오피스 쪽 기능 추가도 하게 해당 세션에 보낼 요청서".
- 고객앱 레퍼런스(이 PC 전용 폴더 `docs/customer-app-design/` — 필요하면 사용자에게 받기): `4. 상품페이지, 상품 아이콘 분류/5. 상품페이지 전체 (2026-11-25 사용자 제공).jpg`, `6. 상품리뷰 전체 보기 (…).jpg`, `2. 뱃지 - *.jpg`, `12. 반품·교환 (배송완료)/`.

## 백엔드 회신 반영(2026-11-25)
- B-2 배너 자리 `PRODUCT_DETAIL` 은 storefront 0.17.0 에 들어갔고, 백엔드가 백오피스에 직접 요청했다(`../pmart-backend/docs/handoff/clients/backoffice/2026-11-25-request-product-detail-banner-placement.md`) — 그 문서를 따른다.
- B-1 의 원산지·소비기한·고시 표는 백엔드가 **지금처럼 notices 글줄로 입력**하고 조회 때 나눈다(product-content 0.9.0) — 백오피스 새 칸은 지금 필요 없다. 설명 묶음·꼬리표는 BR-100 뒤 단계.
- B-4 고객 앱 접수는 **교환만**(반품은 고객센터 — BR-95 결정, ADR-0087 구현 전). 냉장·냉동이 든 교환은 상담원 승인 뒤 진행 — 승인 화면이 필요해진다(계약 나오면).
- B-6 배너 축소본은 서버가 만든다(storefront 0.16.0) — 올리는 화면 변경은 필요 없다.

## 요청 화면

### B-1 상품 편집 — 고객 상품페이지 칸 (BR-100 R1·R2·R6·R11)
고객 상품페이지(레퍼런스)가 칸으로 보이는 값. 지금은 상품 콘텐츠 `notices` 글줄("이름: 값")에 섞여 있어 고객앱은 줄을 읽어 겨우 보인다.
- **원산지**(한 줄 글) — 상품명 아래 회색 줄 "원산지: 상세정보 참고".
- **소비기한/제조일**(한 줄 글) — "구매 전 참고해주세요" 상자.
- **상품정보제공고시 표**(이름·값 여러 줄, 순서) — 고객 "상세정보 ›" 시트.
- **상세 설명 묶음**(순서 있는 블록: 큰 제목 / 글 / 사진 / "옵션N + 옵션 이름" 꼬리표 — 옵션 꼬리표는 그 상품의 SKU 를 고른다) — 고객 "상품설명"(길면 접히고 [상품설명 펼치기]).
- **상품 꼬리표**(여러 개 고르기: 최저가 도전·1+1·신선보장·증정품·사전예약·단독 등 — 종류는 백엔드가 정한 값) — 고객 카드·상세 사진 왼쪽 위.
- 저장은 지금 콘텐츠 승인 흐름 그대로(초안 → 승인 → 게시) — 고객에게는 게시된 값만.

### B-2 배너 편성 — "상품페이지" 자리 (BR-100 R9)
- 배너 자리 고르기에 **상품페이지(PRODUCT_DETAIL)** 추가. 고객 상품페이지 탭 위에 넘기는 배너(레퍼런스 "매일 먹는 계란 특가 2/6"). 실측 약 411×91dp(가로 4.5:1 안팎) — 자리 규격은 `banner-image-specs` 에 백엔드가 더한 값으로.
- 모든 상품에 같은 배너인지, 카테고리별로 고를지는 백엔드 계약대로(요청서에서는 묻기만 했다).

### B-3 기획전(테마) — 고객 "함께 보면 좋은 기획전" (BR-100 R10)
- 고객 상품페이지 아래 카드: 기획전 이름 · "11월 30일까지 · 5일 남음" · 대표 상품 사진 4장 · [전체 보기 ›].
- 편성 화면에 **고객 노출 여부·끝나는 날·대표 이미지(또는 대표 상품 4개 고르기)** 칸이 없으면 더해 주세요. 어떤 상품 페이지에 뜨는지(그 기획전에 든 상품)는 서버가 정한다.

### B-4 고객이 앱에서 접수한 반품·교환 처리 (BR-95)
- 지금 백오피스는 상담원이 **직접 접수**하는 반품만 있다(claim 0.2.0 — 고객 토큰 RETURN 은 422). BR-95 가 열리면 고객이 앱에서 **반품·교환을 접수**한다(품목·수량·이유 13가지·상세 이유·사진 최대 3장·라이더 요청사항, 교환은 재배달).
- 필요한 화면: 고객 접수 건 **목록**(접수 채널 CUSTOMER_APP 구분, 상태·이유·사진 있음) → **상세**(사진 크게, 이유·상세 이유, 회수비 대상 여부) → **승인·거절**(거절 사유) → 회수·재배달 진행 보기. 교환 재고 없음 → 교환 취소 처리.
- 승인·거절 규칙·상태 이름은 백엔드 회신대로.

### B-5 배달 안내 값 설정 (BR-96)
- 고객 홈 "알뜰배달 29~44분 · 최소주문 15,000원", "30,000원부터 배달팁 0원", "배달 안내" 시트(방식별 배달팁 구간, 배송 운영 시간)가 쓰는 **최소 주문 금액·배달팁 구간·운영 시간**.
- 백엔드가 설정 저장소 값으로 두면, 운영자가 바꾸는 화면이 있는지 확인해 주세요(없으면 설정 화면에 더하기 — 바꾸면 승인 흐름이 필요한지는 백엔드와).

### B-6 배너 그림 올리기 안내 (BR-99)
- 지금 LAN 홈 배너가 장당 약 2.2MB PNG 라 고객앱 홈이 늦다. 백엔드가 내려줄 때 줄이기로(요청) — 올리는 화면에는 "사진 배너는 JPG 권장, 큰 PNG 는 내려갈 때 줄어든다" 안내나 용량 경고(지금 maxBytes 5MB)를 백엔드 결정에 맞춰.

## 고객앱 쪽
- 계약이 생기기 전 고객앱은 B-1~B-3 칸을 목에서만 보인다(실서버는 칸을 빼고 그림). B-4 는 고객 신청 화면을 목으로 만들어 두었고, 실서버는 "앱에서 신청할 수 없음 + 고객센터 문의".
- 질문·회신은 이 문서 경로로(또는 PC 1 프론트 세션).

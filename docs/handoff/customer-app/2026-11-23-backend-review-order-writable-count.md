# 요청 — BR-86 리뷰 쓰기 목록의 주문별 쓸 수 있는 품목 수

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (review-service, 지금 0.6.0)
- 계기: 사용자 2026-11-23 "같이 보내". 리뷰관리 › 리뷰 쓰기 탭 초안 04 v3 H(사용자 확정, 앱 반영 45e00a99)의 주문 머리 "11월 19일 배송 · 센터 **3개**"를 지금은 앱이 받아 온 쪽 안의 같은 `orderId` 품목을 세어 보인다. `GET /me/review-eligibilities` 가 쪽 단위라 한 주문의 품목이 쪽 경계에 걸리면 실제보다 적게 보인다(예: 3개 중 1개만 첫 쪽이면 "1개").

## R1. 품목마다 그 주문의 쓸 수 있는 품목 수
- `ReviewEligibility` 에 `orderWritableCount: integer | null` — 같은 주문에서 지금 리뷰를 쓸 수 있는(`REV_ELIGIBLE`·리뷰 없음) 품목 수. 조회 조건(state 등)과 상관없이 그 주문 기준.
- 계산이 무거우면 null 로 두어도 된다(앱은 지금처럼 받은 쪽 안에서 센다).

## 앱(받으면)
- 주문 머리 수를 서버 값으로. null 이면 지금 방식.
- 알림 → 리뷰 쓰기 화면(초안 09-B "쓸 수 있는 리뷰 N개")은 `orderId=` 로 한 주문 전부를 받아 지금도 정확하므로 그대로.

## 급하지 않음
- 지금 LAN 은 한 주문 품목이 적어 쪽 경계에 잘 걸리지 않는다. 다음 review-service 손볼 때 같이 넣어 주시면 된다.

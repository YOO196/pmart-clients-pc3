# 요청 — BR-60 배송지에서 받는 분·연락처 빼기, 연락처는 주문서 "내 연락처"로

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (customer-service 주소록·비회원 배송지·프로필), 참고 order (주문 초안 배송지 사본, BR-37)
- 요청: 사용자 2026-11-19 "처음 주소관리 쪽에 받는분이랑 연락처 있는데 이거 원래 고객앱 레퍼런스쪽에 이런식으로 있던게 맞아?" → "백엔드에 요청서 올리고 그리고 앱도 바꾸자"
- 관련: BR-32 회신 `../pmart-backend/docs/handoff/clients/customer-app/2026-11-19-reply-location-in-url-and-open-items.md` §3·덧붙임(customer 0.7.0 `GET /me` `phone`), BR-37(초안 때 배송지 사본 고정)

## 왜
- 레퍼런스 주소 상세(`customer-app-design/2. …/7-1`, `3-1. …/2-4`)에는 **받는 분·연락처 칸이 없다.**
  지도·도로명·지번·상세주소·라이더 요청사항·공동현관 비밀번호·찾아오는 길 안내만 있다.
- 연락처는 주문하기의 **"내 연락처"**(`6. 주문하기/3`)에서 보이고 "번호 변경"으로 바꾼다. 받는 분 이름 칸은 레퍼런스 어디에도 없다.
- 지금 계약은 `AddressInput` 의 `receiverName`·`receiverPhone` 이 필수다(customer-service `required: [roadAddress, detailAddress, receiverName, receiverPhone]`).
  그래서 앱이 주소를 넣을 때마다(처음 실행 주소, 주소 추가, 비회원 배송지) 이름·연락처를 묻는다.
- 주문 초안은 이 두 값을 배송지에서 사본으로 고정한다(BR-37, 초안 `contact` 는 deprecated).

## 요청
- **R1. 주소 입력에서 받는 분·연락처를 선택으로.** `AddressInput.receiverName`·`receiverPhone` 을 필수에서 뺀다.
  - 회원 주소록(`POST·PATCH /me/addresses`)과 비회원 배송지(`POST /guest-delivery-addresses`) 모두.
  - `Address` 응답에서도 없을 수 있음(null)으로.
  - 이미 저장된 주소의 값은 그대로 둔다(아래 R2 에서 주소 값이 있으면 그것이 먼저).
- **R2. 주문 초안 배송지 사본의 연락처는 회원 연락처에서.** 주소에 값이 없으면 초안을 만들 때 서버가 채운다.
  - 연락처: 프로필 `phone`(BR-32, customer 0.7.0).
  - 받는 분: 프로필 이름(nickname, 없으면 로그인 제공자 이름).
  - 프로필에 연락처가 없으면 초안에 **막힘(blocker) 하나**로 알려 달라(예: `CONTACT_REQUIRED`). 앱은 "내 연락처"를 받아 `POST /me/profile-changes {phone}` 로 저장한 뒤 초안을 다시 만든다.
  - 비회원은 주문하지 않는다(주문서에서 로그인). 그러니 비회원 배송지에는 연락처가 없어도 된다.
- **R3. 주문서 "내 연락처" 번호 변경.** 레퍼런스 6-3 은 주문서에서 번호를 바꾼다. 어느 쪽이 맞는지 정해 달라.
  - (가) 앱이 프로필 연락처를 바꾸고(`profile-changes`) 초안을 다시 만든다 — 새 필드 없음. **앱 추천.**
  - (나) 초안 요청에 "이 주문만" 연락처를 받는다(예: `contactPhone`). deprecated `contact` 를 되살리는 셈이다.
- **R4. 받는 분 이름이 없을 때.** 프로필 이름도 없으면(드묾) 사본 `receiverName` 을 비워도 되는지.
  - 라이더 전달지(`drop-info`)·직원 주문 조회(가린 이름)가 이 값을 쓴다. 비우면 화면이 "이름 없음"으로 보인다. 아니면 R2 처럼 막힘으로.

## 앱이 할 것
- 회신 전(지금 계약 0.7.0):
  - 회원 주소 입력에서 받는 분·연락처 칸을 뺀다. 저장할 때 `GET /me` 의 `phone`·이름으로 채워 보낸다(계약상 아직 필수라서).
  - 프로필에 연락처가 없으면 주소 입력에서 "내 연락처" 한 칸만 묻고, `profile-changes` 로 저장한 뒤 그 값으로 채운다.
  - 비회원 배송지는 프로필이 없어 지금처럼 받는 분·연락처를 묻는다(R1 반영 뒤 뺀다).
  - 주문서는 지금처럼 배송지 사본의 받는 분·연락처를 보인다("번호 변경"은 R3 회신 뒤).
- 회신 뒤: 비회원 배송지 칸도 빼고, R2 막힘·R3 결정대로 주문서 "번호 변경"을 붙인다.

# 요청 — BR-94 LAN 카테고리 묶음(section)·순서를 레퍼런스대로

- 보낸 앱: customer-app (PC 1)
- 받는 백엔드 영역: platform (product-service 카테고리 트리 — ADR-0015 참고 자료 구조, LAN 데이터)
- 계기: 사용자 2026-11-24 "카테고리 지금 묶인대로가 맞는지 확인해줘" → 레퍼런스와 다름. 사용자 결정: "상품 없는 카테고리 일단 숨기고 주류 노출해줘"

## 본 것(LAN `GET /api/v1/categories/tree`, effectiveFrom 2026-11-22T02:30:05Z)
- TOP 17 · SUB 48 · CHIP1 18 · CHIP2 1.
- section 이 있는 TOP 은 옛 시드 3개뿐: `t01` 신선식품(채소·두부·계란)·`t02` 간편식(국·탕·찌개·밀키트·냉동) = 맛있는것, `t03` 생활용품(휴지·물티슈) = 편리한것. 레퍼런스에 없는 카테고리.
- 참고 자료 구조 TOP 14개(`p01`·`p02`·`p03`·`p05`·`p07`·`p08`·`p09`·`p11`·`p12`·`p13`·`p15`·`p17`·`p19`·`p27`)는 **section 이 null** → 앱에는 제목 없는 한 묶음으로 따로 보인다. sortOrder 도 레퍼런스와 다르다(음료·커피·생수 → 문구·사무용품 → 쌀·잡곡·견과 → …).
- 앱은 서버 section·sortOrder 를 그대로 그린다(앱 변경 없음).

## 요청(LAN 데이터, 트리 변경 승인 경로대로)
- R1 옛 시드 TOP `t01`·`t02`·`t03` 숨김(`exposed: false`). 그 아래 상품은 참고 자료 카테고리로 옮겨 주세요(대표 카테고리 포함) — 옮길 곳은 서버 판단.
- R2 section: `p27` 문구·사무용품 = **편리한것**, 나머지 13개(주류 포함) = **맛있는것**.
- R3 sortOrder 를 레퍼런스(카테고리 첫 화면, 왼→오·위→아래) 순서로. 지금 있는 것만:
  - 맛있는것: 밥·도시락(p01) → 라면·면(p02) → 국·탕·찌개(p03) → 분식·야식(p05) → 쌀·잡곡·견과(p07) → 정육·수산·계란(p08) → 음료·커피·생수(p09) → **주류(p19)** → 빵·떡·잼(p11) → 아이스크림(p12) → 우유·유제품(p13) → 햄·어묵·통조림(p15) → 유기농·친환경(p17)
  - 편리한것: 문구·사무용품(p27)
  - 주류는 레퍼런스 첫 화면에 없어 자리를 음료·커피·생수 뒤로 제안한다(다른 자리가 맞으면 서버 판단).
  - 참고 — 레퍼런스 전체 순서. 맛있는것: 밥·도시락, 라면·면, 국·탕·찌개, 요리·반찬, 분식·야식, 과일·채소·샐러드, 쌀·잡곡·견과, 정육·수산·계란, 음료·커피·생수, 과자·초콜릿·시리얼, 빵·떡·잼, 아이스크림, 우유·유제품, 양념·장류·오일, 햄·어묵·통조림, 건강·식단관리, 유기농·친환경(배민이지는 타사 브랜드라 뺌). 편리한것: 헤어·바디·쉐이빙, 세제·방향·탈취, 화장지·생리대, 뷰티·클렌징·선케어, 청소·욕실, 생활잡화·패션, 주방·일회용품, 문구·사무용품, 가전·게임·전기용품, 반려동물, 유아·아동, 건강·의료용품, 홈인테리어.
- R4 **상품 없는 카테고리는 당분간 숨김**(사용자 결정) — 레퍼런스의 나머지 TOP 은 상품이 들어오면 위 순서 자리에 노출. SUB·CHIP 도 상품이 없으면 숨겨 주세요(빈 목록 화면이 생기지 않게). 기준(그 센터 취급 상품 0 인지, 전체 상품 0 인지)은 서버 판단 — 알려 주세요.
- R5 **주류 노출**(사용자 결정) — 지금처럼 노출 유지. 주류 구매 본인 인증(PG)은 따로 정할 일로 남긴다(이 요청 범위 밖).
- Q1 t01~t03 이 LAN 시드(`deploy/lan/seed/seed-data.json`)에서 왔고 p 계열은 나중에 넣으며 section·순서를 안 채운 것인지 — 다시 시드할 때 같은 일이 없게 시드도 맞춰 주세요.

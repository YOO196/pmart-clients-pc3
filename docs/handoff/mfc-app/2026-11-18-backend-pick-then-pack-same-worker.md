# [pmart-clients → pmart-backend] 요청: 피킹을 끝낸 사람에게 그 주문의 패킹을 먼저 (2026-11-18)

- 보낸 앱: mfc-app (PC 3)
- 받는 백엔드 영역: mfc (capacity — 다음 작업 받기, 필요하면 fulfillment)
- 급함: 실서버 피패킹 시험에서 한 주문을 피킹 → 패킹으로 이어 갈 수 없다.

## 증상(LAN, 2026-11-18 사용자 시험)
- 피패킹 업무는 한 주문을 **같은 사람이 피킹하고 바로 패킹**한다(업무 문서 §7-6, 장바구니를 들고 패킹대로 — fulfillment 0.8.0 패킹 때 장바구니 확인).
- PDA 는 피킹이 끝나면 "패킹대 도착 — 패킹 시작"에서 `POST /mfcs/{mfcId}/workers/{workerId}/next-tasks`(workArea `PICK_PACK`)를 부른다.
- 그런데 서버가 **다른 주문의 PICK** 을 준다:

```
02:30:35.756Z fulfillment  작업 ORD-438b0cdc-…-S1-PICK 피킹 완료 — 포장 작업 준비
02:30:37.352Z capacity     다음 작업 PICK ORD-56cd4042-…-S1-PICK → OP-a666a1be-… (시스템 배정)
```
- 같은 때 다른 작업자(OP-990d2c09-…)도 피킹 완료(02:26:55) 뒤 바로 다른 주문 PICK(02:26:57)을 받았다.
- 그 결과 ① 작업자는 장바구니에 앞 주문 상품을 든 채 새 주문 피킹을 시작해야 하고(한 번에 하나라 앞 주문 패킹을 받을 수 없다) ② 앞 주문 PACK 은 담당 없는 READY 로 남아 **장바구니를 들지 않은 다른 사람**에게 갈 수 있다.
- (11-18 01:07 에는 피킹 완료 9초 뒤 받아서 우연히 같은 주문 PACK 이 왔다 — 순서가 정해져 있지 않다.)

## 원인(읽은 코드)
- `AssignmentService.pullNext`: 들고 있는 배정이 없으면 담당 없는 READY 작업 전체를 `rank`(PICK·PACK 같은 3) → `promisedReadyAt` → taskId 순으로 고른다. **방금 피킹한 사람·같은 출고** 를 보지 않는다.
- `TaskStore.releasePack`: 피킹이 끝나면 PACK 을 `worker_id` 없이 READY 로 연다 — 피킹한 사람이 남지 않는다.

## 요청
- **R1.** 다음 작업 받기에서 그 작업자가 **방금 끝낸 PICK 의 같은 출고 PACK** 이 READY(담당 없음)면 다른 후보보다 먼저 준다. 업무가 `PICK_PACK` 이고 PACK 자격이 있을 때.
  - 대안: 피킹 완료 때 PACK 을 그 피커에게 바로 배정(`NEXT_TASK` 와 같은 SYSTEM 배정)해서, 다음 받기가 "들고 있는 작업"으로 그 PACK 을 돌려주게.
  - 어느 쪽이든 PDA 는 바뀌지 않는다(지금도 다음 작업이 PACK 이면 바로 패킹 화면).
- **R2.** 같은 출고 PACK 을 피커가 아닌 사람에게 주지 않는다 — 피커가 휴게·퇴근·정지면 센터 관리자 재배정으로만(장바구니를 넘겨받아야 하므로). 이 규칙이 맞는지 결정이 필요하면 회신에 적어 달라.
- **R3.** 지금 LAN 에 남은 것 정리: `ORD-438b0cdc-ec2e-39b7-a84f-5e5446252a01-S1-PACK` 이 담당 없는 READY 로 남아 있다(피커 OP-a666a1be-… 는 다른 주문 PICK 을 들고 있음). R1 배포 뒤 그 피커가 받을 수 있게 하거나 센터 관리자 배정으로.

## 참고 — 클라이언트에서 같이 고친 것
- PDA 가 배정 직후 fulfillment 가 아직 READY(배정 사건 전)인 작업에 시작을 보내지 않던 것 → READY 도 시작(클라이언트 PR #108, 병합). 서버 변경 필요 없음.
- PDA "패킹 끝" 이 PACK 실행을 보내 422 `UNSUPPORTED_EXECUTION` 받는 것 → 서버는 모든 집품분이 밀봉되면 PACK 을 스스로 COMPLETED 로 한다(`PackageService`) — PDA 에서 그 실행을 빼고 출고 상태로 끝을 판단하도록 고친다. 서버 변경 필요 없음.

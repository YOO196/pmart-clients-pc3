# [pmart-clients → pmart-backend] 요청: LOT 라벨(QR·자체 스티커) 발급 — 피킹에서 LOT 를 찍어 선입선출 확인 (2026-11-17)

- 보낸 앱: mfc-app (PC 3)
- 받는 백엔드 영역: mfc (inbound · inventory · fulfillment)
- 사용자 결정(2026-11-17)
  - "QR 이나 자체 상품 바코드(스티커로 붙이는 것)는 **로트 기준으로 발급**하고 싶다. 로트를 구분할 수 있어야 유통기한 선입선출이 가능하다."
  - 붙이는 단위: **상품 하나마다**. **박스 상품만 박스에**.
  - LOT 하나에는 **제조사·공급사·유통기한·납입일이 같은 상품**이 여러 개 묶인다. 같은 LOT 의 상품은 같은 라벨 값을 쓴다.
  - 라벨이 없거나 훼손되면 **재출력**해서 찍는다. 상품 바코드(880…·299…)로 대신 넘어가지 않는다.
  - 피킹 수량: 첫 개는 반드시 스캔, 그다음은 스캔마다 +1, **+ 버튼**, **수기 입력**(지시 수량까지).

## 1. 왜
- 지금 PDA 가 찍는 상품 바코드는 SKU 만 알려 준다. 같은 SKU 라도 LOT(유통기한)가 다른 실물을 구분할 수 없다.
- 피킹 지시는 이미 LOT 단위로 온다(`TaskLine.picks[].lotId` — 유통기한 순). 하지만 작업자가 지시와 다른 LOT 을 집어도 PDA 가 알 수 없고, 재고가 `LOT_MISMATCH` 로 거절해야 비로소 드러난다.
- 업무 원문(WMS)도 상품 바코드와 LOT 라벨을 따로 확인하고, 라벨을 다시 뽑아도 같은 식별자를 유지한다고 한다(WMS-business-logic §위치 검증 · "라벨 재출력은 같은 식별자를 유지").
- 계약에는 LOT 라벨이 없다. 지금 라벨 형식은 송장 `TRF:{trfId}:{version}`, 포장 `PKG:{packageId}:{version}` 뿐이다.

## 2. 요청

| # | 요청 | 비고 |
|---|---|---|
| L1 | **LOT 라벨 값 형식**을 정한다. 예 `LOT:{lotId}`(기존 `{유형}:{id}` 규칙). LOT 한 개 = 값 한 개, 재출력해도 같은 값 | `lotId` 가 길면(UUID) 스티커용 짧은 코드를 따로 두어도 된다 — 그때는 짧은 코드 ↔ lotId 를 계약에 |
| L2 | **LOT 를 만드는 순간(입고 검수 합격·초기 재고 적재)에 라벨 값과 인쇄 정보**를 응답이나 조회로 준다: 라벨 값, SKU, 상품명, 유통기한, 제조사·공급사, 납입일, **붙일 장수**(낱개 수, 박스 상품이면 박스 수) | PDA 가 사내 라벨 프린터로 뽑는다 |
| L3 | **재출력 조회**: LOT(또는 라벨 값)로 같은 인쇄 정보 — 위치·SKU 로도 찾을 수 있게(라벨이 훼손돼 값을 모를 때) | 재출력은 물류 실적이 아니다 |
| L4 | **라벨 값 해석**: 찍은 값 → `{lotId, sku, expiryDate, qualityState}` | PDA 가 지시 LOT 와 대조하고, 재고 확인·이동·실사에도 쓴다 |
| L5 | 박스 상품: 박스 라벨 1개 = 박스 안 수량(입수) N. 피킹·이동에서 박스 라벨 한 번이면 N 개로 보는지, 낱개로 풀면 어떻게 하는지 | 박스 상품 표시 필드(예 `packUnit`, `unitsPerBox`)가 상품 정보에 필요 |
| L6 | LOT 묶음 기준(제조사·공급사·유통기한·납입일이 같으면 같은 LOT)이 지금 LOT 생성 규칙과 같은지 확인 | 다르면 회신 — 사용자 결정 필요 |

## 3. PDA 흐름(L1~L4 가 오면)
- **입고(검수 → 적치)**: LOT 이 생기면 "LOT 라벨 N장 출력"(낱개마다, 박스 상품은 박스마다). 출력 실패·훼손은 재출력.
- **피킹**: 장바구니 → 칸 → **LOT 라벨 한 번** → 수량(1부터, 스캔마다 +1, + 버튼, 수기 — 지시 수량까지) → 지시 수량에 닿으면 실적 전송.
  - 지시 LOT 와 다르면 "유통기한 순서가 아닌 LOT 예요"로 막는다(실적에 넣지 않음).
  - 라벨이 없거나 안 찍히면 재출력 후 찍는다.
- **이동·적치·실사·재고 확인**: 같은 라벨로 LOT 를 확인한다.

## 4. 지금 PDA (회신 전)
- 수량 입력(첫 개 스캔 → 스캔·+·수기)은 지금 계약으로 먼저 만들었다. 첫 스캔은 상품 바코드(`TaskLine.barcodes`)이고, LOT 은 지시된 LOT 로 본다(검증 없음).
- L1~L4 가 오면 첫 스캔을 LOT 라벨로 바꾼다.
